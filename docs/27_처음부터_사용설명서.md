# 27. 처음부터 사용 설명서 (개발자가 아니어도 따라 하는 순서) — v1.3

> 이 문서와 저장소(git) 파일만 있으면 **내 PC 에서 서버·DB·메일함까지 띄우고 확인**할 수 있다. 모든 명령은 그대로 복사해서 붙여 넣는다. 막히면 §9 표에서 증상을 찾는다.
> 운영 서버를 사고 설정하는 방법은 [28번](./28_운영서버_구입_설정_가이드.md). 설치 상세·브랜치 규칙은 [25번](./25_새PC_설치와_브랜치_운영.md).
> **현재 상태**: 서버·DB·메일함에 더해 **업체·관리자 웹과 출연자 앱의 실제 화면이 있다.** 새 PC 에서 처음부터 하는 순서는 §3(설치) → §4(켜기) → §5(확인)이다.

## 1. 전체 그림 (내 PC 안에서 이렇게 돈다)
| 부품 | 하는 일 | 어디서 도는가 | 확인 주소 |
|---|---|---|---|
| PostgreSQL 18 | 모든 데이터 보관(개발용, 지워도 됨) | Docker 컨테이너 `infra-postgres-1` | `localhost:5432` |
| Mailpit | 서버가 보낸 메일을 받아 보여 주는 가짜 메일함 | Docker 컨테이너 `infra-mailpit-1` | http://localhost:8025 |
| 백엔드(서버) | 가입·로그인·업체 승인 등 규칙을 처리 | 내 PC 의 Java 프로그램 | http://localhost:8080 |
| 업체·관리자 웹(React) | 업체의 공고·지원자·인원표, 관리자 승인 | 내 PC 의 Node 프로그램 | http://localhost:5173 |
| 출연자 앱(Flutter) | 출연자의 가입·지원·확정·QR | 내 PC 의 Flutter 프로그램(브라우저로 봄) | http://localhost:5000 |

## 2. 준비물
- Windows 11 PC(메모리 16GB 권장, 최소 8GB), 인터넷, GitHub 계정(저장소 접근 권한).
- 설치할 것은 §3 한 번이면 끝난다. **프로젝트 폴더는 반드시 WSL 안(`~/…`)** 에 둔다(`C:` 아래는 매우 느림).

## 3. 한 번만: 설치 (새 컴퓨터에서도 이 순서 그대로)
총 30~60분(다운로드 포함). 순서를 지킨다.
1. **WSL 과 Ubuntu**: [25번 §2-1](./25_새PC_설치와_브랜치_운영.md) (PowerShell 에서 `wsl --install -d Ubuntu-24.04`, `.wslconfig` 작성) 후 PC 재시작.
2. **도구 설치** — [25번 §2-2](./25_새PC_설치와_브랜치_운영.md) 에 명령이 전부 있다. 설치하는 것과 확인 명령:

| 도구 | 용도 | 설치 후 확인 |
|---|---|---|
| git | 코드 받기 | `git --version` |
| Docker Engine | DB·메일함 | `docker ps` (오류 없이 표가 나오면 됨) |
| JDK 25 | 서버 | `java -version` → 25 |
| Node 24 | 업체·관리자 웹 | `node -v` → v24 |
| Flutter 3.47.8 | 출연자 앱 | `flutter --version` → 3.47.8 |

3. **저장소 받기**(WSL 창에서):
```bash
mkdir -p ~/docker && cd ~/docker && git clone https://github.com/7fsikMinQ/O.git o
```
```bash
cd ~/docker/o && git checkout dev/mk && git pull
```
4. **설치 점검**(아무것도 켜지 않고 확인만):
```bash
cd ~/docker/o && tools/dev/bootstrap.sh --check
```
`✘` 가 하나라도 나오면 그 줄의 안내를 따른다. 모두 `✔` 면 통과(Node·Flutter 는 `!` 경고면 아직 안 깐 것).
5. **프로젝트 패키지 받기**(처음 한 번, 인터넷 필요):
```bash
cd ~/docker/o/web && npm install
```
```bash
cd ~/docker/o/app && flutter pub get
```
(`npm install` 끝의 "4 high severity vulnerabilities" 는 개발 도구 경고이므로 무시한다. `npm audit fix --force` 는 금지 — 일부러 고정한 버전이 깨진다.)
6. **DB 처음 만들기**:
```bash
cd ~/docker/o && tools/dev/reset-db.sh
```

## 4. 매일: 켜기 · 끄기 (터미널 3개)
WSL 창(터미널)을 **3개** 연다. 각 창에서 돌리는 프로그램은 끝나지 않고 계속 도는 것이 정상이다. **창을 닫으면 그 프로그램도 꺼진다.** SSH 접속은 WSL 이 꺼질 수 있어 `wsl` 창을 권장한다.

**터미널 1 — DB·메일함과 서버** (가장 먼저)
```bash
cd ~/docker/o && tools/dev/up.sh
```
```bash
cd ~/docker/o/backend && ./gradlew bootRun
```
`Started BojoHelpApplication` 줄이 나오면 준비 완료. 화면 맨 아래 `80% EXECUTING … > :bootRun` 은 정상(서버가 도는 중).

**터미널 2 — 업체·관리자 웹** (서버가 켜진 뒤)
```bash
cd ~/docker/o/web && npm run dev
```
Windows 브라우저로 http://localhost:5173

**터미널 3 — 출연자 앱** (서버가 켜진 뒤)
```bash
cd ~/docker/o/app && flutter run -d web-server --web-port 5000
```
첫 빌드는 몇 분. `lib/main.dart is being served at http://localhost:5000` 이 나오면 Windows 브라우저로 http://localhost:5000 을 연다. (WSL 에는 크롬이 없어 `-d chrome` 은 쓰지 않는다. "10 packages have newer versions" 는 무시.)

| 보는 곳 | 주소 |
|---|---|
| 업체·관리자 웹 | http://localhost:5173 |
| 출연자 앱 | http://localhost:5000 |
| 메일함(확인 메일·인증번호는 여기서 본다) | http://localhost:8025 |
| 서버 건강 확인 | http://localhost:8080/actuator/health |

**끄기**: 각 터미널에서 `Ctrl+C`. DB·메일함까지 끄려면:
```bash
cd ~/docker/o && docker compose -f infra/docker-compose.dev.yml down
```
(데이터는 남는다. 지우려면 §6 의 초기화.) **다음에 다시 켤 때**는 §4 만 같은 순서로 한다.

**관리자 로그인**: 웹 로그인 화면에서 아이디 `admin`, 비밀번호 `admin` → 2차 비밀번호 칸이 나오면 `admin1234`. (개발용 값이다.)

**전체 시험 순서**: ① 웹에서 업체 가입 → 메일함의 확인 링크 → 로그인 → 업체 등록(사업자번호·등록증은 비워도 됨) → ② 관리자로 로그인해 승인 → ③ 업체로 공고 작성(일정·역할·시급) → ④ 앱에서 이메일로 가입(메일함의 6자리) → 프로필·주민번호 등록 → 공고에 지원(사진·서명) → ⑤ 웹에서 합격 통보 → ⑥ 앱에서 "참여할게요" → ⑦ 웹에서 인원표·메시지·출퇴근 QR.

## 5. 눈으로 확인하기
| 확인 | 명령/주소 | 정상 결과 |
|---|---|---|
| 서버 건강 | `curl -s localhost:8080/actuator/health` | `{"groups":["liveness","readiness"],"status":"UP"}` |
| 켜진 기능 목록 | `curl -s localhost:8080/features` | 정산·송금 등은 전부 `false` |
| API 문서(개발에서만) | 브라우저로 http://localhost:8080/swagger-ui.html | 목록이 보임 |
| 받은 메일 | 브라우저로 http://localhost:8025 | 서버가 보낸 인증·임시 비밀번호 메일 |
| 테이블 수 | `docker exec -i infra-postgres-1 psql -P pager=off -U app -d app -c "\dt" \| tail -3` | `(73 rows)` (앱 72 + Flyway 이력 1) |
| 모든 SQL 기록 | `docker logs -f infra-postgres-1` (`Ctrl+C` 로 빠져나옴) | `statement:` / `execute …` 줄이 흐른다. 값은 안 보이는 것이 정상 |

> `docker exec` 에 `-it` 를 쓰고 `| tail` 을 붙이면 멈춘 것처럼 보인다(페이지 넘김 프로그램 때문). `-i` 만 쓰고 `-P pager=off` 를 붙인다.

### 5-1. 출연자 가입 체험 (인증번호는 메일로 온다 — 개발에서는 Mailpit)
기본 설정(`OTP_CHANNEL=email`)에서는 출연자도 **이메일로 온 6자리**로 가입한다(문자 대행사는 쓰지 않아 비용 0원). 앱 화면에서는 이메일 입력 → 인증번호 → 이름·약관 동의 순서이고, 같은 일을 명령으로 하면:
1. 번호 요청:
```bash
curl -s -X POST localhost:8080/auth/otp/send -H 'Content-Type: application/json' -d '{"email":"actor1@example.com"}'
```
2. 브라우저로 http://localhost:8025 (Mailpit)를 열어 메일의 6자리 숫자를 본다(180초 안에, 5번 틀리면 막힘):
```bash
curl -s -X POST localhost:8080/auth/otp/verify -H 'Content-Type: application/json' -d '{"email":"actor1@example.com","code":"123456"}'
```
3. 처음이면 `{"status":"NEED_SIGNUP","signupToken":"…"}` 가 온다. 약관 번호는 `curl -s localhost:8080/terms` 로 보고, 필수 약관 번호를 넣어 가입:
```bash
curl -s -X POST localhost:8080/auth/signup -H 'Content-Type: application/json' -d '{"signupToken":"위 토큰","name":"홍길동","agreedTermIds":[1,2,3]}'
```
(약관 번호는 실제 `/terms` 결과의 필수 항목으로 바꾼다.) 성공하면 `accessToken`/`refreshToken` 이 온다.
- 문자로 받고 싶으면 서버를 `OTP_CHANNEL=sms` 로 켠다(요청 값은 `{"phone":"010-…"}`). 개발에서는 진짜 문자 대신 서버 창에 `[DEV SMS]` 줄이 찍힌다. 운영에서 문자 대행사를 연결하지 않은 상태(`SMS_PROVIDER=none`)에서는 요청이 성공으로 끝나지만 아무것도 보내지 않는다.

### 5-2. 업체·관리자 체험 (이메일, 메일은 Mailpit 에서 읽는다)
- **관리자**는 서버를 처음 켤 때 자동으로 1명 만들어진다: 아이디 `admin`, 비밀번호 `admin`(개발 기본값. 바꾸려면 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 환경변수). 관리자로 로그인하면 **2차 비밀번호 칸**이 추가로 나온다 — 값은 `admin1234` 이고 DB 의 수정 불가 테이블에 고정되어 있다(공개 서비스 전에는 TOTP 로 교체 권장).
- 업체 가입 → Mailpit 의 확인 메일 링크 → 업체 등록 → 관리자로 로그인해 승인. 아래 5-3 의 웹 화면에서 클릭으로 한다.
- 비밀번호를 잊었을 때: 로그인 화면의 "비밀번호 찾기" → Mailpit 의 임시 비밀번호(30분) → 그걸로 로그인하면 **비밀번호 변경만 가능한 상태**가 되고 새 비밀번호를 정한다.

### 5-3. 실제 화면 보기 (업체·관리자 웹 / 출연자 앱)
서버(`bootRun`)와 Mailpit 이 켜져 있어야 한다. **새 WSL 창**에서:
```bash
cd ~/docker/o/web && npm install && npm run dev
```
브라우저로 http://localhost:5173 — 업체 가입·로그인, 공고 작성, 지원자 보기·합격 통보, 인원표·QR, 메시지, 관리자 화면. 관리자는 `admin` / `admin` 후 2차 비밀번호 `admin1234`.

출연자 앱은 Flutter 가 필요하다(설치: 12번 문서). 브라우저에서 보려면:
```bash
cd ~/docker/o/app && flutter run -d chrome --web-port 5000
```
(서버가 `localhost:5000` 출처를 허용하도록 개발 기본값이 들어 있다. 서버 주소를 바꾸려면 `--dart-define=API_BASE=http://주소:8080`.) Android 에뮬레이터는 `--dart-define=API_BASE=http://10.0.2.2:8080`.

**자동으로 전체 흐름 보기**(개발자용): 서버·Mailpit·웹이 켜진 상태에서 `node tools/e2e/web_flow.mjs --shots=/tmp/shots` 는 실제 브라우저로 업체 가입 → 승인 → 공고 → 지원 → 합격 통보를 끝까지 돌며 화면 캡처를 남긴다.

## 6. 최신 받기 · 초기화
**새 코드 받기**(Claude 가 `dev/mk` 를 갱신하면):
```bash
cd ~/docker/o && git checkout dev/mk && git pull
```
- `pathspec 'dev/mk' did not match` 가 나오면 먼저 `git fetch` 후 다시 한다.
- 서버를 켰는데 `Migration checksum mismatch` 같은 Flyway 오류가 나면 **개발 DB 를 초기화**한다(데이터가 지워진다 — 개발용이라 괜찮다):
```bash
cd ~/docker/o && tools/dev/reset-db.sh
```
초기화 직후 DB 는 비어 있다. **서버를 한 번 켜면(`bootRun`) 테이블 72개가 자동으로 만들어진다.**

## 7. 시험(자동 점검) 돌리기
```bash
cd ~/docker/o/backend && ./gradlew test --no-daemon
```
- 끝에 `BUILD SUCCESSFUL` 이면 통과(몇 분). 실제 건수는:
```bash
cd ~/docker/o/backend && python3 -c "
import glob,re
t=f=e=s=0
for p in glob.glob('build/test-results/test/*.xml'):
    m=re.search(r'tests=\"(\d+)\" skipped=\"(\d+)\" failures=\"(\d+)\" errors=\"(\d+)\"',open(p,encoding='utf-8').read(2000))
    a,b,c,d=map(int,m.groups()); t+=a;s+=b;f+=c;e+=d
print('전체',t,'건너뜀',s,'실패',f,'오류',e)"
```
- 시험은 자기 DB 를 따로 띄우므로 개발 DB 데이터에 영향이 없다.
- 설계 검증(스키마 제약 27건·동시성·문서 연결): `tools/verify_all.sh` — PostgreSQL 클라이언트(`psql`)가 필요하며 개발자용이다.

## 9. 문제 해결 표
| 증상 | 원인 | 해결 |
|---|---|---|
| `docker: command not found` | Docker 미설치 | [25번 §2-2](./25_새PC_설치와_브랜치_운영.md) |
| `permission denied … docker.sock` | 사용자가 docker 그룹이 아님 | `sudo usermod -aG docker $USER` 후 WSL 창을 닫고 다시 연다 |
| `docker-credential-desktop.exe not found` | Docker Desktop 흔적 | `echo '{}' > ~/.docker/config.json` |
| 5432 포트가 이미 사용 중 | 다른 PostgreSQL 이 켜져 있음 | `.env` 의 `DB_PORT=5433` 과 `DB_URL` 포트를 같이 바꾸고 다시 켠다 |
| SSH 로 접속했더니 얼마 뒤 연결이 끊김/서버 꺼짐 | WSL 이 유휴 종료 | `.wslconfig` 에 `vmIdleTimeout=-1`, 가능하면 `wsl` 창으로 작업 |
| 시험 중 연결이 끊김 | 메모리 부족 | `.wslconfig` 의 `memory=8GB` 이상, WSL 재시작 |
| `Migration checksum mismatch` | 개발 DB 가 옛 스키마 | §6 `reset-db.sh` |
| `relation "users" does not exist` | DB 만 새로 만들고 서버를 안 켬 | `bootRun` 한 번 실행 |
| `Did not find any tables` | 위와 같음 | 위와 같음 |
| `git checkout dev/mk` → pathspec 오류 | 원격 브랜치를 아직 모름 | `git fetch` 후 다시 |
| `psql … the database system is shutting down` | 컨테이너가 재시작 중 | 10초 뒤 다시 |
| `80% EXECUTING` 에서 멈춘 것처럼 보임 | 정상(서버가 돌고 있음) | `Ctrl+C` 로 끝낼 때까지 그대로 |
| `\dt \| tail` 이 멈춤 | `-it` 의 페이지 넘김 | `-it` 대신 `-i`, `-P pager=off` |
| 로그인이 15분 막힘 | 같은 계정·같은 IP 5회 실패 잠금(정상 기능) | 15분 기다리거나 다른 IP 에서 시도. 잠긴 순간 계정 주인에게 알림 메일이 간다 |
| `flutter: command not found` | Flutter 미설치/경로 없음 | [25번 §2-2](./25_새PC_설치와_브랜치_운영.md) 의 Flutter 설치, 이미 했다면 WSL 창을 닫았다 다시 연다 |
| 앱 화면이 안 뜨거나 가입 때 네트워크 오류 | 서버(터미널 1)가 꺼졌거나 5000 이 아닌 포트로 연 경우 | 서버 확인, `--web-port 5000` 으로 다시 실행(서버가 이 출처만 허용) |
| 웹 화면이 안 뜸 | 서버가 꺼짐 또는 `npm install` 안 함 | 터미널 1 확인, `cd web && npm install` |
| 메일이 안 온다 | 개발은 진짜 메일이 아니라 Mailpit | http://localhost:8025 |
| 프로젝트가 너무 느림 | `/mnt/c/…` 아래에 있음 | WSL 홈(`~/docker/o`)으로 옮긴다 |

## 10. 용어
- **WSL2**: Windows 안에서 도는 리눅스. **Docker**: 프로그램(DB 등)을 상자(컨테이너)에 담아 똑같이 돌리는 도구. **Flyway**: DB 모양(테이블)을 버전 순서대로 자동으로 만드는 도구. **Mailpit**: 개발용 가짜 메일함. **Testcontainers**: 시험 때만 임시 DB 를 띄우는 도구. **아웃박스**: 보낼 메일·알림을 DB 에 먼저 적고 별도 일꾼이 보내는 방식(유실 방지). **JWT**: 로그인 증표. **해시**: 되돌릴 수 없게 바꾼 값(비밀번호·전화번호 보관용).

## 11. 하면 안 되는 것
1. `.env`, `.env.prod`, 비밀번호·키를 git 에 올리지 않는다(`.gitignore` 가 막지만 직접 `-f` 로 올리지 않는다).
2. 운영 서버의 개인정보를 내 PC 로 복사하지 않는다.
3. `dev/mk` 에 직접 커밋하지 않는다(코드 수정은 Claude 에게 요청).
4. 개발 DB 비밀번호(`app`/`app`)를 운영에 쓰지 않는다.
5. 개발 서버 포트(5432·8080·8025)를 공유기에서 열지 않는다(포트포워딩 금지, [18번](./18_운영서버_보안_가이드.md)).

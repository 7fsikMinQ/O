# 27. 처음부터 사용 설명서 (개발자가 아니어도 따라 하는 순서) — v1.3

> 이 문서와 저장소(git) 파일만 있으면 **내 PC 에서 서버·DB·메일함까지 띄우고 확인**할 수 있다. 모든 명령은 그대로 복사해서 붙여 넣는다. 막히면 §9 표에서 증상을 찾는다.
> 운영 서버를 사고 설정하는 방법은 [28번](./28_운영서버_구입_설정_가이드.md). 설치 상세·브랜치 규칙은 [25번](./25_새PC_설치와_브랜치_운영.md).
> **정직한 현재 상태**: 서버(백엔드)·DB·메일 흐름은 실제로 돈다. **업체 웹·출연자 앱의 실제 화면은 아직 없다**(HTML 시안만 있음, §8). 지금은 API·메일함·DB 로 확인한다.

## 1. 전체 그림 (내 PC 안에서 이렇게 돈다)
| 부품 | 하는 일 | 어디서 도는가 | 확인 주소 |
|---|---|---|---|
| PostgreSQL 18 | 모든 데이터 보관(개발용, 지워도 됨) | Docker 컨테이너 `infra-postgres-1` | `localhost:5432` |
| Mailpit | 서버가 보낸 메일을 받아 보여 주는 가짜 메일함 | Docker 컨테이너 `infra-mailpit-1` | http://localhost:8025 |
| 백엔드(서버) | 가입·로그인·업체 승인 등 규칙을 처리 | 내 PC 의 Java 프로그램 | http://localhost:8080 |
| 화면(웹·앱) | 사용자가 보는 화면 | 아직 시안 단계 | `docs/mockups/*.html` |

## 2. 준비물
- Windows 11 PC(메모리 16GB 권장, 최소 8GB), 인터넷, GitHub 계정(저장소 접근 권한).
- 설치할 것은 §3 한 번이면 끝난다. **프로젝트 폴더는 반드시 WSL 안(`~/…`)** 에 둔다(`C:` 아래는 매우 느림).

## 3. 한 번만: 설치
1. **WSL 과 Ubuntu**: [25번 §2-1](./25_새PC_설치와_브랜치_운영.md) (PowerShell 에서 `wsl --install -d Ubuntu-24.04`, `.wslconfig` 작성).
2. **도구 설치**: [25번 §2-2](./25_새PC_설치와_브랜치_운영.md) (git·Docker Engine·JDK 25·Node 24).
3. **저장소 받기**(WSL 창에서):
```bash
mkdir -p ~/docker && cd ~/docker && git clone https://github.com/7fsikMinQ/O.git o
```
```bash
cd ~/docker/o && git checkout dev/mk && git pull
```
4. **설치 점검**(아무것도 켜지 않고 확인만):
```bash
cd ~/docker/o && tools/dev/bootstrap.sh --check
```
`✘` 가 하나라도 나오면 그 줄의 안내를 따른다. 모두 `✔` 면 통과.

## 4. 매일: 켜기 · 끄기
**켜기** (WSL 창 2개를 쓴다. 창을 닫으면 서버도 꺼진다. SSH 접속은 WSL 이 꺼질 수 있어 **`wsl` 창 권장**):
```bash
cd ~/docker/o && tools/dev/up.sh
```
(DB·메일함 컨테이너가 켜진다.) 두 번째 단계 — 서버 실행:
```bash
cd ~/docker/o/backend && ./gradlew bootRun
```
화면 맨 아래에 `80% EXECUTING … > :bootRun` 이 보이면 **정상**이다(서버가 계속 도는 중이라는 표시, 끝나지 않는다). `Started BojoHelpApplication` 줄이 나오면 준비 완료.

**끄기**: 서버 창에서 `Ctrl+C`. DB 까지 끄려면:
```bash
cd ~/docker/o && docker compose -f infra/docker-compose.dev.yml down
```
(데이터는 남는다. 데이터까지 지우려면 §6 의 초기화.)

## 5. 눈으로 확인하기
| 확인 | 명령/주소 | 정상 결과 |
|---|---|---|
| 서버 건강 | `curl -s localhost:8080/actuator/health` | `{"groups":["liveness","readiness"],"status":"UP"}` |
| 켜진 기능 목록 | `curl -s localhost:8080/features` | 정산·송금 등은 전부 `false` |
| API 문서(개발에서만) | 브라우저로 http://localhost:8080/swagger-ui.html | 목록이 보임 |
| 받은 메일 | 브라우저로 http://localhost:8025 | 서버가 보낸 인증·임시 비밀번호 메일 |
| 테이블 수 | `docker exec -i infra-postgres-1 psql -P pager=off -U app -d app -c "\dt" \| tail -3` | `(72 rows)` (앱 71 + Flyway 이력 1) |
| 모든 SQL 기록 | `docker logs -f infra-postgres-1` (`Ctrl+C` 로 빠져나옴) | `statement:` / `execute …` 줄이 흐른다. 값은 안 보이는 것이 정상 |

> `docker exec` 에 `-it` 를 쓰고 `| tail` 을 붙이면 멈춘 것처럼 보인다(페이지 넘김 프로그램 때문). `-i` 만 쓰고 `-P pager=off` 를 붙인다.

### 5-1. 출연자 가입 체험 (문자 인증, 개발에서는 진짜 문자 대신 서버 창에 번호가 찍힌다)
1. 번호 요청:
```bash
curl -s -X POST localhost:8080/auth/otp/send -H 'Content-Type: application/json' -d '{"phone":"010-1234-5678"}'
```
2. **서버를 켠 창**에 `[DEV SMS] … 인증번호 123456 …` 줄이 찍힌다. 그 숫자 6자리를 아래에 넣는다(180초 안에, 5번 틀리면 막힘):
```bash
curl -s -X POST localhost:8080/auth/otp/verify -H 'Content-Type: application/json' -d '{"phone":"010-1234-5678","code":"123456"}'
```
3. 처음이면 `{"status":"NEED_SIGNUP","signupToken":"…"}` 가 온다. 약관 번호는 `curl -s localhost:8080/terms` 로 보고, 필수 약관 번호를 넣어 가입:
```bash
curl -s -X POST localhost:8080/auth/signup -H 'Content-Type: application/json' -d '{"signupToken":"위 토큰","name":"홍길동","agreedTermIds":[1,2,3]}'
```
(약관 번호는 실제 `/terms` 결과의 필수 항목으로 바꾼다.) 성공하면 `accessToken`/`refreshToken` 이 온다.

### 5-2. 업체·관리자 체험 (이메일, 메일은 Mailpit 에서 읽는다)
- 최초 관리자는 **서버를 켜는 창에서** 환경변수를 지정하면 첫 기동 때 1명 만들어진다(이미 있으면 건너뜀):
```bash
cd ~/docker/o/backend && export ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='Admin12345678' && ./gradlew bootRun
```
- 업체 가입(`POST /auth/email/signup`) → Mailpit 에서 확인 메일의 링크/토큰 → `POST /auth/email/verify` → 업체 등록 → 관리자로 로그인(`POST /auth/email/login`)해 승인(`/admin/companies/…`). 모든 경로·값은 Swagger 화면에서 입력해 눌러 볼 수 있다.
- 비밀번호를 잊었을 때: `POST /auth/password/reset-request` → Mailpit 의 임시 비밀번호(30분) → 그걸로 로그인하면 **비밀번호 변경만 가능한 상태**가 되고 `PUT /me/password` 로 새 비밀번호를 정한다.

## 6. 최신 받기 · 초기화
**새 코드 받기**(Claude 가 `dev/mk` 를 갱신하면):
```bash
cd ~/docker/o && git checkout dev/mk && git pull
```
- `pathspec 'dev/mk' did not match` 가 나오면 먼저 `git fetch` 후 다시 한다.
- 서버를 켰는데 `Migration checksum mismatch` 같은 Flyway 오류가 나면 **개발 DB 를 초기화**한다(데이터가 지워진다 — 개발용이라 괜찮다):
```bash
cd ~/docker/o && tools/dev/reset-db.sh
```
초기화 직후 DB 는 비어 있다. **서버를 한 번 켜면(`bootRun`) 테이블 71개가 자동으로 만들어진다.**

## 7. 시험(자동 점검) 돌리기
```bash
cd ~/docker/o/backend && ./gradlew test --no-daemon
```
- 끝에 `BUILD SUCCESSFUL` 이면 통과(몇 분). 실제 건수는:
```bash
cd ~/docker/o/backend && python3 -c "
import glob,re
t=f=e=s=0
for p in glob.glob('build/test-results/test/*.xml'):
    m=re.search(r'tests=\"(\d+)\" skipped=\"(\d+)\" failures=\"(\d+)\" errors=\"(\d+)\"',open(p,encoding='utf-8').read(2000))
    a,b,c,d=map(int,m.groups()); t+=a;s+=b;f+=c;e+=d
print('전체',t,'건너뜀',s,'실패',f,'오류',e)"
```
- 시험은 자기 DB 를 따로 띄우므로 개발 DB 데이터에 영향이 없다.
- 설계 검증(스키마 제약 26건·동시성·문서 연결): `tools/verify_all.sh` — PostgreSQL 클라이언트(`psql`)가 필요하며 개발자용이다.

## 9. 문제 해결 표
| 증상 | 원인 | 해결 |
|---|---|---|
| `docker: command not found` | Docker 미설치 | [25번 §2-2](./25_새PC_설치와_브랜치_운영.md) |
| `permission denied … docker.sock` | 사용자가 docker 그룹이 아님 | `sudo usermod -aG docker $USER` 후 WSL 창을 닫고 다시 연다 |
| `docker-credential-desktop.exe not found` | Docker Desktop 흔적 | `echo '{}' > ~/.docker/config.json` |
| 5432 포트가 이미 사용 중 | 다른 PostgreSQL 이 켜져 있음 | `.env` 의 `DB_PORT=5433` 과 `DB_URL` 포트를 같이 바꾸고 다시 켠다 |
| SSH 로 접속했더니 얼마 뒤 연결이 끊김/서버 꺼짐 | WSL 이 유휴 종료 | `.wslconfig` 에 `vmIdleTimeout=-1`, 가능하면 `wsl` 창으로 작업 |
| 시험 중 연결이 끊김 | 메모리 부족 | `.wslconfig` 의 `memory=8GB` 이상, WSL 재시작 |
| `Migration checksum mismatch` | 개발 DB 가 옛 스키마 | §6 `reset-db.sh` |
| `relation "users" does not exist` | DB 만 새로 만들고 서버를 안 켬 | `bootRun` 한 번 실행 |
| `Did not find any tables` | 위와 같음 | 위와 같음 |
| `git checkout dev/mk` → pathspec 오류 | 원격 브랜치를 아직 모름 | `git fetch` 후 다시 |
| `psql … the database system is shutting down` | 컨테이너가 재시작 중 | 10초 뒤 다시 |
| `80% EXECUTING` 에서 멈춘 것처럼 보임 | 정상(서버가 돌고 있음) | `Ctrl+C` 로 끝낼 때까지 그대로 |
| `\dt \| tail` 이 멈춤 | `-it` 의 페이지 넘김 | `-it` 대신 `-i`, `-P pager=off` |
| 로그인이 15분 막힘 | 같은 계정·같은 IP 5회 실패 잠금(정상 기능) | 15분 기다리거나 다른 IP 에서 시도. 잠긴 순간 계정 주인에게 알림 메일이 간다 |
| 메일이 안 온다 | 개발은 진짜 메일이 아니라 Mailpit | http://localhost:8025 |
| 프로젝트가 너무 느림 | `/mnt/c/…` 아래에 있음 | WSL 홈(`~/docker/o`)으로 옮긴다 |

## 10. 용어
- **WSL2**: Windows 안에서 도는 리눅스. **Docker**: 프로그램(DB 등)을 상자(컨테이너)에 담아 똑같이 돌리는 도구. **Flyway**: DB 모양(테이블)을 버전 순서대로 자동으로 만드는 도구. **Mailpit**: 개발용 가짜 메일함. **Testcontainers**: 시험 때만 임시 DB 를 띄우는 도구. **아웃박스**: 보낼 메일·알림을 DB 에 먼저 적고 별도 일꾼이 보내는 방식(유실 방지). **JWT**: 로그인 증표. **해시**: 되돌릴 수 없게 바꾼 값(비밀번호·전화번호 보관용).

## 11. 하면 안 되는 것
1. `.env`, `.env.prod`, 비밀번호·키를 git 에 올리지 않는다(`.gitignore` 가 막지만 직접 `-f` 로 올리지 않는다).
2. 운영 서버의 개인정보를 내 PC 로 복사하지 않는다.
3. `dev/mk` 에 직접 커밋하지 않는다(코드 수정은 Claude 에게 요청).
4. 개발 DB 비밀번호(`app`/`app`)를 운영에 쓰지 않는다.
5. 개발 서버 포트(5432·8080·8025)를 공유기에서 열지 않는다(포트포워딩 금지, [18번](./18_운영서버_보안_가이드.md)).

# 11. 운영·유지보수 지침서 (v1.2)

> v1.0 · 2026-10-28 · 대상: 운영자 겸 개발자(1~2인). 명령은 예시이며 실제 호스트·경로에 맞게 조정.

## 1. 운영 원칙
1. **데이터 먼저**: 장애 시 서비스 복구보다 데이터 보존이 우선. 모든 변경 전 백업 확인.
2. **개인정보 최소 열람**: 운영 목적 외 조회 금지, 열람은 `audit_logs` 로 남는다. 운영자 계정과 **자사 보출 업체 계정을 분리**하고 자사 공고·지원자도 일반 업체와 같은 규칙으로 처리한다(이해충돌 방지).
3. **변경은 작게, 자주, 되돌릴 수 있게**: 마이그레이션은 앞/뒤 호환(expand → migrate → contract).
4. **설정은 코드 배포 없이**: 정책 값은 `app_settings`(관리자 화면, 변경 감사).

## 3. 모니터링 · 알림 기준
| 지표 | 경고 | 심각 | 도구 |
|---|---|---|---|
| API 5xx 비율 | >1% 5분 | >5% | Sentry/메트릭 |
| API p95 | >800ms 10분 | >2s | Actuator/Micrometer |
| DB 디스크 | 70% | 85% | 호스트 모니터링 |
| DB 연결 | 풀 80% | 풀 고갈 | Hikari 메트릭 |
| outbox NEW 적체 | >500 | >5,000 | 메트릭 |
| 푸시 실패율 | >5% | >20% | `notification_deliveries` |
| 백업 | 24h 미성공 | 48h 미성공 | J11 |
| 인증 실패 급증 | 평시 3배 | 10배 | 로그인 이력 |
| 업타임 | 1회 실패 | 2회 연속 | UptimeRobot(5분) |
알림은 운영자 메신저/이메일로 전달한다(무료 채널).

## 4. 백업 · 복구
**정책**: 일 1회 논리 백업(J11) + 보관 30일(주간 12주), 암호화 후 R2 별도 버킷(운영 버킷과 분리, 삭제 방지 권한). 성장 시 WAL 아카이빙(pgBackRest/WAL-G)으로 RPO 단축. 목표 **RPO 24h / RTO 4h**(MVP).
```bash
# 백업 (J11 이 수행하는 내용)
pg_dump -Fc -h "$DB_HOST" -U "$DB_USER" "$DB_NAME" | age -r "$BACKUP_PUBKEY" > "backup_$(date +%F).dump.age"
# 업로드: S3 호환 CLI 로 R2 버킷에 저장
```
```bash
# 복구 리허설 (분기 1회, 격리된 임시 DB 에서)
age -d -i backup.key backup_YYYY-MM-DD.dump.age | pg_restore -h localhost -U postgres -d restore_test --clean --if-exists
psql -h localhost -U postgres -d restore_test -c "SELECT count(*) FROM users;"
```
복구 후 점검: 행 수 대조, 앱 기동 후 로그인·지원 스모크 테스트, 소요 시간 기록(RTO 검증).

## 5. 배포 · 롤백
1. CI 통과(테스트·라이선스·OpenAPI 대조) → 이미지 태그 `YYYYMMDD-gitsha`.
2. **마이그레이션 선적용**(Flyway, 하위 호환 변경만) → 앱 `docker compose pull && up -d`.
3. 헬스체크(`/actuator/health`) 통과 확인, 스모크 5종(로그인·달력·지원·합격·알림함).
4. 실패 시 이전 이미지 태그로 `up -d`. 스키마는 expand 단계만 배포하므로 롤백 가능. 파괴적 변경(contract)은 별도 릴리스에서 데이터 이전 확인 후.
5. 배포는 **촬영 임박 시간대(촬영 집합 2시간 전~종료 시간대, 새벽 촬영 전후) 금지**. 점검 공지는 `공지` 게시판 + 푸시.

## 6. 장애 대응 플레이북
| 증상 | 1차 확인 | 조치 |
|---|---|---|
| 푸시가 안 간다 | `notification_deliveries` FAILED 사유, FCM 키/쿼터, 토큰 무효율 | 키 교체, 재발송 도구, 급하면 반장 전화 리스트(미응답자 API) 사용 |
| 앱 전체 느림/오류 | 5xx, DB 연결/락, 디스크 | 슬로우 쿼리 확인, 긴 트랜잭션 종료, 재시작 |
| 지원 정원 이상(초과/미반영) | `v_schedule_headcount_summary` vs 실제 count | J10 재계산 후 원인 분석(동시성 버그 의심 시 즉시 개발 우선순위) |
| 로그인 장애 | 토큰 서명키, 소셜 제공자 상태 | 이메일 로그인 우회 안내 |
| 개인정보 유출 의심 | 감사로그, 접근 로그 | 접근 차단·키 회전·영향 범위 확정, **법정 신고·통지 절차** 진행(13번 §5) |
| 스토리지 오류 | R2 상태, 서명 URL 시계 오차 | 재시도, 상태 페이지 확인 |
| 당일 대량 노쇼 | 참석확인 응답률 | 마감 후 추가 합격(가용 지원자 메시지) + 긴급 공고 복사 게시 |
| 디스크 가득 | 로그·덤프·WAL | 오래된 로그 압축/삭제, 백업 로컬 사본 삭제(원격 보관 확인 후) |

## 7. 일상 점검표
**매일(5분)**: 업타임·에러 알림, 백업 성공, outbox/푸시 적체, 미처리 업체 승인·동의서·신고·문의.
**매주**: 슬로우 쿼리 상위 10, 디스크·DB 크기 추이, 의존성 보안 경보, 정합성 리포트(J10, J13).
**매월**: 비용 점검(무료 한도 소진율: R2·메일·FCM), 접근 권한 재검토(관리자·반장 계정), 로그인 이상 징후, 약관/설정 변경 이력 검토.
**분기**: 복구 리허설, 시크릿·키 회전(`key_version` 증가 + 재암호화 배치), 의존성 업그레이드, 부하 테스트.

구체적 기간은 **법무·세무 확인 후 `app_settings` 로 고정**한다. "무기한 전부 보관"은 개인정보보호법상 허용되지 않을 수 있다.

## 9. 접근 통제 · 계정
- 관리자·운영자: 개인 계정, 2단계 인증, 공용 계정 금지. 퇴사/역할 변경 즉시 회수(`user_roles`).
- 서버 접근: SSH 키 전용, 비밀번호 로그인 비활성, 접근자 최소화.
- DB 직접 조회는 읽기 전용 계정만, 민감 컬럼은 복호화 키 없이 의미 없음. 운영 DB 데이터를 개발 환경으로 복사 금지(필요 시 비식별).
- 업체 직원 퇴사 시 OWNER 가 즉시 `REMOVED` 처리(세션 폐기 포함).

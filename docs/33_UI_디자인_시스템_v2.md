# 33. UI 디자인 시스템 v2 — 토스·당근처럼 깔끔하게, "AI 느낌" 최소 (v1, 2026-11-19)

> 사용자 요구: 토스·당근 앱처럼 **깔끔하고 가시성 좋게**, **AI 가 만든 느낌을 최대한 줄이고**, 앱 화면과 사이트 모두 **폰트·색상·크기**를 정리하며 **무료·저작권 문제 없는 것만** 쓴다. 이 문서는 [15번](./15_UI_UX_디자인시스템.md)의 **시각 언어(파스텔·이모지·둥근 카드)를 대체**한다(15번의 화면 원칙·접근성 기준은 유지).
> ⚠️ 토스·당근의 로고·아이콘·전용 폰트·브랜드 색을 **복제하지 않는다.** 원칙(밀도·여백·위계·문구)만 참고한다. 근거 자료: 당근 [SEED 디자인 시스템](https://github.com/daangn/seed-design)(오픈소스, 구조 참고), 폰트 라이선스는 §3 표.

## 1. "AI 느낌"을 만드는 것과 피하는 법
| 흔한 AI 티 | 우리 규칙 |
|---|---|
| 보라·청보라 그라디언트, 네온 | **그라디언트·글로우 금지.** 단색 면만 사용 |
| 이모지 남발(버튼·제목마다) | **UI 에 이모지 사용 금지**(⭐ 출연자 표시 같은 도메인 기호만 예외, §6). 아이콘은 선형 아이콘 세트 |
| 모든 것이 둥근 카드+그림자+유리 효과 | 카드는 **1px 테두리, 반경 12 이하, 그림자 없음**. 구분은 여백과 선으로 |
| 과한 둥근 pill 버튼·큰 장식 일러스트 | 버튼 반경 10, 일러스트 없음(빈 화면도 글 한 줄) |
| "✨ 멋진 결과를 만들어 보세요!" 같은 들뜬 문구 | **짧은 평서문**. 느낌표·수식어 금지, 숫자와 사실 먼저 |
| 모든 정보를 같은 크기·같은 굵기 | **위계 3단계**(제목·본문·보조)와 숫자 강조 |
| 카드 안에 카드 | 한 단계만. 목록은 구분선으로 |
| 장식용 애니메이션 | 상태 변화에만 150ms 이내 전환 |

## 2. 원칙 (토스·당근에서 가져올 것)
1. **한 화면 한 목적**, 핵심 행동 1개(하단 고정 버튼 1개, 앱), 사이트는 우측 상단 주 버튼 1개.
2. **숫자·상태 먼저**: 날짜·시간·남은 인원·상태가 가장 먼저 보인다.
3. **큰 글자·넓은 여백**: 본문 16(앱)·15(웹), 터치 영역 48 이상(주 버튼 52).
4. **문구가 UI 의 절반**: 해요체, 짧게, 다음 행동을 말한다("일정을 등록해요", "승인을 기다리고 있어요").
5. **실수 방지**: 삭제·취소·권한 변경은 **영향 범위를 보여 주는 확인 창**과 사유 입력.
6. **같은 말은 같은 표현**: 용어집 고정(§7).

## 3. 폰트 (전부 무료·상업 이용 가능)
| 용도 | 폰트 | 라이선스 | 비고 |
|---|---|---|---|
| 본문·제목(앱·웹) | **Pretendard** (가변 폰트) | SIL OFL 1.1 ([공식 저장소](https://github.com/orioncactus/pretendard): 글꼴 단독 판매 외 상업 이용·수정·재배포 허용) | 한글+라틴+숫자 한 벌. **서버에 직접 포함(CDN 의존 없음)** |
| 대체(fallback) | 시스템 폰트(`-apple-system`, `Roboto`, `Noto Sans KR`) | 각 OS 기본 | Pretendard 로딩 전·실패 시 |
| 숫자(표·금액) | Pretendard 의 `tabular-nums` | 〃 | 자릿수 정렬 |
- 라이선스 문구(OFL.txt)를 저장소 `licenses/` 에 보관하고 앱 설정 화면의 "오픈소스 라이선스"에 표시한다. **(◐ 최신 라이선스는 배포처에서 도입 시점에 재확인)**
- 한글 웹폰트는 용량이 크므로 **서브셋(자주 쓰는 한글 + 라틴)** 을 만들어 `woff2` 로 제공(초기 로딩 150KB 이하 목표). Flutter 는 앱에 폰트 파일을 번들.
- 폰트는 **1종만** 쓴다(굵기 400/500/700). 장식 폰트 없음.

## 7. 문구 규칙·용어집
- 해요체, 한 문장 20자 안팎, 느낌표·이모지·"~해 보세요!" 금지, 부정 표현 완화("실패했어요" → "저장하지 못했어요. 다시 시도해 주세요").
- 오류는 **원인 + 다음 행동**(예: "승인이 필요한 기능이에요. 대표에게 권한을 요청해 주세요").
| 용어 | 표기 |
|---|---|
| 일정 / 촬영 | 촬영 일정 |
| 필요 인원 | 필요 인원 (정원은 내부 용어, 화면엔 "필요 인원") |
| 팀장 등록 | 팀장 등록 / 팀장 등록 취소 |
| 승인 대기 | 승인 대기 |
| 삭제 | **삭제**(관리자·윗 직급만 보임), 그 외는 "취소" 또는 "숨기기" |
| 직급 / 권한 | 직급, 권한 |

## 8. 사유 입력 컴포넌트 (신청·취소·삭제 공통)
선택지 라디오 목록 + 마지막 "기타" 선택 시 텍스트 입력(200자, 필수). 선택지 목록은 서버 설정(`reason_catalog`)에서 내려받아 **관리자가 화면에서 수정**할 수 있게 한다. 기본 목록은 31번 §4-6.

## 9. 화면 목록 — "확실한 테스트 화면"부터

> **2026-11-20 화면 번호 통일**: 화면 번호는 개발 제안서(`docs/proposal`)의 체계를 기준으로 한다 — 직원 웹 `SW01~SW34`, 직원 앱 `SM01~SM12`, 출연자 앱·웹 `AM01~AM24`, 구매자 `BW01~BW05`, 추가 기능 예시 `OP01~OP04`(총 79개, 목록은 제안서 부록 C). 아래 표의 구 번호 대응: W01→SW01, W02→SW02, W03→SW03, W04→SW04, W05→SW05, W06→SW07, W07→SW08, W08→SW09, W09→SW11, W10→SW13, W11→SW14, W12→SW15, W13→SW16, W14→SW17, W15→SW19, W16→SW20. 제안서에서 새로 추가된 화면: SW06(월 보기), SW10(작품), SW12(직원 상세), SW18(사유 선택지), SW21~SW32(3·4단계 직원측), SW33·SW34(주간·일간 보기), SM·AM·BW·OP 전부.

## 11. 구현 방법
- **토큰 단일 원천**: `design/tokens.json` → 웹 `tokens.css`, 앱 `tokens.dart` 를 스크립트로 생성(값이 두 곳에서 어긋나지 않게). 기존 `web/src/styles/tokens.css`·`app/lib/core/ui/tokens.dart` 를 이 값으로 교체.
- 기존 화면은 **토큰과 구성 요소만 바꿔도 대부분 새 모양**이 되도록 이미 `core/ui` 조립 규칙을 지켜 왔다(이모지 제거와 문구 정리는 화면별 수정 필요).
- 자동 점검: `tools/ui_audit.js`(겹침·잘림·대비·터치 영역) 기준에 **이모지 사용 금지 검사**, **그라디언트·그림자 사용 금지 검사**, **폰트 1종 검사**를 추가.
- 시험 화면 접근: `/dev/ui` 는 `NODE_ENV=development` 에서만 라우트 등록.

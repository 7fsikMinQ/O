# 31. OIO 캐스팅 플랫폼 최종 설계 (v3, 2026-11-19) — 직원 사이트 → 앱 → 출연자 DB → 외부 제공

> 사용자 확정(2026-11-16, 11-19)을 반영한 **전체 설계의 기준 문서**다. OIO(법인, 단역·이미지단역·보조출연 캐스팅)가 쓰는 플랫폼을 **4단계로 키운다**: ① 직원 전용 사이트 → ② 앱(플레이스토어·앱스토어) → ③ 외부 배우·출연자 등록과 인재 DB(프로필·오디션 영상·이력서) → ④ 인재 DB 외부 제공(판매).
> **확정**은 사용자가 정한 것, **제안**은 Claude 가 권하는 것(사용자 확인 전 코드 반영 안 함)이다. 외부 사실은 2차 자료라 ◐(미확인)이다. v2 의 "스토어 제출은 이용자 영역을 켠 뒤에"는 이 문서가 **대체**한다(§6).

## 0. 확정 사항 (사용자)
1. 소속은 **OIO 법인**. 다루는 유형은 **보조출연·단역·이미지단역**(외국인은 제외, 국내만).
2. **단계적 확장**: 처음엔 **직원들만 쓰는 사이트** → 이후 **앱**으로 확장 → 그 뒤 **다른 배우·출연자도 가입·등록**하며 **DB·오디션 영상·이력서**를 받고 → 나중에 그 DB 로 관리하고 **판매도** 한다.
3. 직원 직급: 대표, 이사, 현장 실장, 현장 팀장, 스케줄러, 캐스팅 매니저 등(목록 확장 가능). 총괄(개발자)은 전부 수정·삭제 가능.
4. 선발은 스케줄러·이사·대표. 팀장 등록은 즉시 확정·수정 가능·삭제는 윗 직급. 신청·취소 사유는 선택지+기타 직접 작성.
5. 웹앱(PWA) + 플레이스토어 + 앱스토어. 이용자(출연자) 영역은 **개발되어 있어도 숨겨 두고** 준비되면 공개.
6. 스토어 계정은 **OIO 법인 명의**.

## 1. 한눈에 — 4단계
| 단계 | 누가 쓰나 | 핵심 가치 | 규모(대략, 확정 아님) |
|---|---|---|---|
| **1. 직원 사이트** | OIO 직원만 | 촬영 일정·필요 인원·**팀장 등록**·인원 배정을 한곳에서. 내부 인원 명부 | 4~6주 |
| **2. 앱 확장** | 직원(현장 포함) | 휴대폰 직원 모드(오늘 일정·팀장 등록·QR·전화), 스토어 등록 | 4~6주 |
| **3. 출연자 공개 + 인재 DB** | 외부 배우·출연자 + 직원 | 가입·프로필·**이력서·오디션 영상**·신청·확정, 직원은 인재 DB 로 선발·관리 | 6~8주 |
| **4. 외부 제공(판매)** | 제작사·감독 등 외부 구매자 | 인재 열람·검색·캐스팅 제안(구독/건별) | 6주+ |
각 단계는 **앞 단계가 안정된 뒤** 시작한다. 이미 만든 출연자 앱·API·시험은 3단계에서 **켜기만 하면 되도록** 보존한다(`ACTOR_AREA` 스위치, §5).

## 3. 1단계 — 직원 사이트 (가장 먼저)

### 3-1. 핵심 설계 결정: "내부 인원 명부"
1단계에는 출연자가 아직 가입하지 않는데도 직원은 **누가 어느 촬영에 가는지** 관리해야 한다. 그래서 **로그인 없는 출연자 행**을 허용한다.
- `users` 에 상태 `UNCLAIMED`(미가입)를 추가: 직원이 이름·전화·유형·사진·메모로 등록한 인원. 로그인 계정이 없을 뿐 **기존 지원·출결·메시지 구조를 그대로 재사용**한다(지원서 테이블을 새로 만들지 않음).
- 직원이 일정에 **직접 배정**하면 `CONFIRMED`(직원 확정, 전화로 확인)로 기록한다. 2단계 확정(출연자 클릭)은 3단계에 가입한 사람에게만 적용.
- 3단계에서 출연자가 같은 전화·이메일로 가입하면 인증 후 **기존 행에 계정을 연결(claim)**한다. 과거 출연 이력이 그대로 이어진다.
- **개인정보 주의(◐)**: 직원이 입력한 출연자 정보는 수집 동의 근거가 필요하다. 명부 등록 시 "동의 받음(방법·일자)" 표시 칸을 둔다.

### 3-2. 기능
| 영역 | 내용 |
|---|---|
| 일정 | 작품·촬영일정(날짜·시간·장소)·필요 인원(유형·요건·정원). 저장하면 공개 상태에 따라 반영, 신청자·배정자가 있는 일정을 바꾸면 알림, 초안 표시 |
| 팀장 | 일정별 팀장 등록(본인/대신)·수정·삭제, "팀장 N명 필요/M명 등록", 사유 선택지+기타 |
| 배정 | 인원 명부에서 검색→일정에 배정, 겹침·간격 경고(기존), 정원 동시성(기존) |
| 명부 | 유형(보조출연·단역·이미지단역, 복수)·사진·키/몸무게 등·메모·출연 이력, 노쇼 횟수 |
| 현장 | 인원표·출결(QR 대신 직원 체크)·단체 알림(기존 재사용) |
| 관리 | 직원 초대·직급·권한(총괄·대표), 감사 로그, 삭제/복구 |
| 숨김 | 이용자 가입·공고·신청 화면 숨김(`ACTOR_AREA` 끔) |

### 3-3. 운영 전 필수 (직원 사이트가 인터넷에 열리므로 순서가 앞당겨짐)
| 항목 | 이유 | 제안 |
|---|---|---|
| 운영 서버·도메인 | 직원이 외부에서 접속 | 28번 가이드 그대로(Lightsail+Cloudflare). 트래픽이 작아 서버는 작게 시작 |
| 실제 메일 발송 | 직원 초대·비밀번호 재설정 | Resend 등 SMTP, SPF/DKIM(28번 §7) |
| **관리자·대표 2차 인증(TOTP)** | 직원 개인정보 접근 | 고정 2차 비밀번호는 개발용이므로 **운영 전 TOTP 로 교체** |
| 접근 제한 | 외부 공격면 축소 | 직원 사이트를 **Cloudflare Access**(조직 직원만 로그인, 소규모 무료 플랜이 있다고 알려짐 ◐)나 IP 제한으로 한 번 더 감쌈 |
| 백업 | 개인정보·일정 보존 | 28번 §9 |
| Turnstile | 로그인 대입 공격 | 직원 전용+Access 면 우선순위 낮춤, 3단계(출연자 공개) 전 필수 |

## 4. 2단계 — 앱 확장
- **직원 모바일(현장)**: Flutter 앱에 **직원 모드**: 오늘 일정, 팀장 등록·취소, 인원 체크/QR 스캔, 전화 걸기. PC 업무(일정표·표·엑셀·권한)는 웹 유지. 웹뷰만 씌운 앱은 애플 심사에서 거절될 수 있다(◐)고 보고 Flutter 로 만든다.
- **스토어 등록**: 직원 전용 앱도 **심사용 데모 계정**을 주면 등록할 수 있다. 공개 목록이 부담이면 애플 **비공개 배포(Unlisted)**·구글 **내부/비공개 트랙**을 쓸 수 있다(◐ 최신 정책 확인).
- **법인 계정**: 구글 플레이 조직 계정(D-U-N-S 필요, 최대 30일 ◐), 애플 조직 계정(연 US$99, D-U-N-S·조직 도메인 이메일·공개 웹사이트 필요 ◐). **2단계 시작 3~4주 전에 신청**을 권한다(1단계 개발과 병행).
- iOS 는 Mac 없이 클라우드 빌드(Codemagic 등)로 제출 가능(◐), 푸시 시험엔 아이폰 실기기 1대 필요.
- 앱 이름·아이콘·처리방침·계정 삭제 화면은 기존 준비물 재사용. **서비스 이름**(OIO vs 보조출연 헬프)을 정해야 한다(§8).

## 5. 3단계 — 출연자 공개 + 인재 DB

### 5-1. 공개 방식
`feature_flags` 에 **`ACTOR_AREA`**(출연자 영역). 개발 PC=켬(기존 시험 유지), 운영 1·2단계=끔, 3단계에 켬. 끔일 때 출연자 가입·로그인·공고 조회 API 는 404, 앱·웹 첫 화면의 "이용자로 시작" 숨김.

### 5-2. 인재 DB (출연자가 직접 입력·업로드)
| 영역 | 내용 |
|---|---|
| 프로필 | 유형 복수, 사진(PROFILE/FULL_BODY, 기존 5MB·EXIF 제거), 신체·스타일 태그, 의상 사이즈, 활동 지역 |
| **이력서** | 경력 항목(작품·역할·연도·연출/제작사·비고)을 여러 줄로 입력 + 이력서 파일(PDF) 업로드(5MB) |
| **오디션 영상** | 영상 업로드(권장 한도: 1건 3분·200MB, 3개까지) 또는 외부 링크(YouTube 비공개 등). 직원·허가된 구매자만 재생(서명 URL) |
| 동의 | 수집·이용, **제3자 제공(외부 제공 4단계)을 별도 항목으로**, 영상·이력서 보유기간, 철회 |
| 공개 범위 | 출연자가 "OIO 내부만 / 외부 제공 허용"을 고른다(기본: OIO 내부만) |
| 관리 | 직원은 인재 DB 검색(유형·신체·경력)·태그·메모·선발 추천, 미완성 프로필 알림 |
- **영상 저장 비용(◐ Cloudflare 공식 문서 인용 블로그)**: R2 는 저장 약 US$0.015/GB·월, 내려받기 무료. Stream 은 저장 US$5/1,000분, 재생 US$1/1,000분(인코딩·플레이어 포함). **제안: 처음엔 R2 + 업로드 시 서버 확인만, 재생은 서명 URL 로 직접 재생**(브라우저 호환 mp4/H.264 로 제한)하고, 영상이 많아지면 Stream 도입. 영상 크기·개수 한도로 비용 상한을 둔다.
- 기존 `FileStorage` 어댑터에 R2 구현을 추가(운영 전 필수)하고 영상은 **큰 파일 직접 업로드(서명 URL)** 경로를 새로 만든다(현재는 서버 경유 5MB).

## 6. 4단계 — 외부 제공(판매)
> "판매"를 **제작사·감독·외부 에이전시에게 인재 DB 를 열람·검색·제안할 수 있게 하고 대가를 받는 것**으로 해석했다. 다르면 알려 주세요(§8).

| 항목 | 제안 |
|---|---|
| 구매자 계정 | 외부 구매자 조직(제작사 등)·담당자 계정, OIO 승인제 |
| 판매 방식 후보 | ① 월 정액 구독(열람·검색) ② 건별 열람권/연락권 ③ **캐스팅 의뢰**(구매자가 조건 제시 → OIO 가 추천, 성사 수수료). 기존 `subscription_plans`·`plan_features`·`company_subscriptions` 재사용 가능 |
| 노출 정책 | 출연자가 **"외부 제공 허용"한 사람만** 노출. **연락처는 비공개 — 연락은 OIO 가 중개**(구매자가 제안 → OIO → 출연자 동의 시 연결) |
| 열람 기록 | 누가 누구를 언제 봤는지 로그, 출연자가 확인 가능, 철회 시 즉시 비노출 |
| 가격·정산 | 구독료 결제는 PG(카드) 연동 필요(별도 작업). 금액은 OIO 결정 |
- **법적 주의(◐, 확인 필요)**: 이 단계는 이전 "법무 확인 생략" 결정의 전제(중개·지원서만)와 **범위가 다르다**. 출연자 정보를 **유상으로 제3자에게 제공**하려면 개인정보 **제3자 제공 별도 동의**와 고지가 필요하고, 구인·구직 정보를 제공·알선하면 **직업정보제공사업 신고/직업소개 등록 대상 여부**를 따져야 한다([직업안정법 제19조 안내](https://korea.legal/wiki/%ec%a7%81%ec%97%85%ec%95%88%ec%a0%95%eb%b2%95-%ec%a0%9c19%ec%a1%b0/): 국내 유료직업소개는 사업소 관할 지자체 등록, 정해진 요금 외 금품 수수 금지). 또 캐스팅·출연 알선 업체는 **대중문화예술기획업 등록** 대상이라는 보도가 있다([2025 보도](https://www.segye.com/newsView/20250918504519)) — OIO 가 이미 등록했는지 확인이 필요하다. **1~3단계는 현 결정대로 진행하고, 4단계 착수 전에 노무사·변호사 확인을 권한다.**

## 7. 기술·구현 매핑
### 7-1. 구조 (변경 없음)
모듈러 모놀리스(Spring Boot) 1개 + PostgreSQL + React 직원 웹 + Flutter 앱(직원 모드+출연자 모드). 새 서비스·인프라는 R2(1~2단계 사진, 3단계 영상)와 결제(4단계)뿐.

# 15. UI/UX 디자인 시스템

> v1.0 · 2026-10-28 · 목표: 출연자 앱은 **토스·당근처럼 간결하고 따뜻한 모바일 UX**, 업체/관리자 웹은 **MUI·shadcn 수준의 정돈된 업무 UI**.
> ⚠️ 토스·당근의 **로고·아이콘·전용 폰트·브랜드 색을 복제하지 않는다.** "느낌"(원칙·밀도·모션)만 참고하고 고유한 색·이름을 쓴다.

## 1. 디자인 원칙
| 원칙 | 의미 | 적용 |
|---|---|---|
| 한 화면 한 목적 | 화면마다 핵심 행동 1개 | 하단 고정 CTA(56dp) 1개, 보조 행동은 텍스트 버튼 |
| 큰 글씨·넓은 여백 | 눈이 편하고 실수 감소 | 본문 16sp↑, 카드 패딩 16~20, 섹션 간격 24 |
| 숫자·상태를 먼저 | 현장 판단에 필요한 정보 우선 | 일당·집합시각·남은 인원을 카드 상단에 굵게 |
| 단계적 폼 | 한 번에 다 묻지 않기 | 지원 폼 2단계, 자동 입력, 바텀시트 |
| 따뜻한 말투 | 거절·오류도 상처 최소화 | "마감되어 선발되지 않았어요" (불합격=붉은색 금지) |
| 신뢰 신호 | 안전한 서비스 느낌 | 성실도·출석 횟수·업체 승인 배지 |
| 즉각 피드백 | 기다림 최소화 | 스켈레톤, 낙관적 업데이트, 실행 취소 토스트, 햅틱 |
| 실수 방지 | 위험 동작은 확인 | 영향 인원 수를 보여주는 확인 바텀시트 |

## 4. 구현 가이드
### Flutter (출연자 앱)
- `ThemeData(useMaterial3: true)` 를 기반으로 `ColorScheme` 를 토큰으로 직접 지정하고, 추가 토큰은 `ThemeExtension<AppTokens>` 로 제공(상태 색, 간격, 모서리).
- 위젯 레이어: `core/ui`(Button, Chip, Card, BottomSheet…)를 먼저 만들고 기능 화면은 이것만 조립(직접 색/크기 하드코딩 금지).
- 달력: `table_calendar` + 커스텀 `CalendarBuilders`. 목록: `SliverList` + 스켈레톤(`skeletonizer`). 이미지: `cached_network_image` + 썸네일 variants.
- 푸시 딥링크: GoRouter 경로 `/applications/:id`, `/applications/:id/departure`, `/field/schedules/:id/attendance` 등 알림 `link_path` 와 1:1.
- 접근성: Semantics 라벨, 글자 확대 1.3배 테스트, 터치 타겟 점검.
### 웹 (업체·관리자)
- Tailwind v4 CSS 변수에 토큰을 정의하고 shadcn/ui 컴포넌트가 이를 참조하게 한다. (MUI 가 더 익숙하면 MUI Core(MIT) + 동일 토큰으로 대체 가능하나, 번들·커스터마이징 면에서 shadcn 을 기본으로 한다. MUI X Data Grid 의 Pro/Premium 기능은 유료이므로 쓰지 않는다.)
- 반응형: 사이드바 ↔ 하단 내비 전환, 그리드는 모바일에서 카드 뷰로 폴백. 반장 현장 기능은 앱이 1순위, 웹은 폴백.
- 표 밀도 토글(편안함/촘촘함), 키보드 단축키(일괄 선택·합격), 인쇄용 스타일(인원표·정보표).

## 2. 데이터 모델 분석
1. **분리 원칙 유지**: 계정/권한/프로필, 파일(+다형성 첨부), 게시판, 공고·일정·역할·지원. 업체·출연자·관리자는 `user_roles` 로 다중 역할.
2. **핵심 불변식은 DB 가 최후 방어**: 정원, 활성 중복 지원, 겹침 확정 EXCLUDE(override 제외), 공고당 패널티 1건, 주민번호 해시 유일, 일정 길이·허용 오차 범위, 플래그·상태 CHECK.
3. **증빙 구조**: 지원서 스냅샷+서명 메타+주민번호 버전 참조. 합격서는 지원서/일정에서 **생성**하는 문서(금액 없음).
4. **시간 모델**: 내부 시각(`start_at/end_at`, KST 생성열)은 계산용, 화면은 예상(±2h/±4h)만.
5. **돈**: 정산·이체 배치·플래그 OFF, 송금 실행 상태 없음.
6. **개인정보 열**: 주민번호(AES-GCM+해시), 계좌(암호화), 휴대폰(해시는 OTP 용 별도), 주소·신체 정보. 로그·응답 금지는 코드 규칙으로 강제 필요 → 구현 시 시험.
7. **이번 분석에서 찾은 보완**: ① 외래키 열 중 **조인·삭제 경로가 있는 22개에 인덱스 추가**(예: `applications.schedule_id`, `job_broadcast_recipients.application_id`, `notification_deliveries.notification_id`, `audit_logs.actor_user_id`). ② 나머지 외래키 62개는 관리자 처리자·승인자 등 **저빈도 열이라 의도적으로 제외**(쓰기 비용 대비 이득 없음). ③ ⭐·읽음 확인·OTP·삭제 요청·차단 테이블 추가.

## 3. 소스 구조(구현 지침)
- 모듈러 모놀리스 `{base}.{module}.{api|application|domain|infra}`; 모듈은 05번 PGM-B01~B17. 인증(B01)은 문자 OTP·토큰, 공고(B05)·지원(B07)·출결(B08)·정산(B09, 플래그)·메시지(B13)·알림(B12).
- 트랜잭션 경계: 합격 통보(정원 락)·확정(겹침 검사: **override 포함 전체 SELECTED/CONFIRMED**)·아웃박스 같은 트랜잭션.
- 플래그 검사는 **서버 필터 한 곳**(꺼진 기능 404), 클라이언트는 `/app/config` 로 메뉴 숨김.
- 모든 민감 열람·내보내기 AOP 감사.
- OpenAPI → 클라이언트 생성만 사용(손으로 만든 호출 금지).

## 4. UI 분석·설계
### 4.1 화면 구성
- 출연자 앱 하단 탭 5개: **홈 · 일 찾기 · 내 일정 · 메시지 · 내 정보**. 상단 종 아이콘=알림. 흐름 화면(지원·서명·합격)은 탭을 숨기고 **"← 뒤로" + 하단 큰 버튼 1개**.
- 업체 웹: 좌측 사이드바, 표 중심(인원 정보표, 공지 읽음 현황, ⭐ 명단). 현장(반장) 모드는 출석·미응답자·공지·명단만.
### 4.2 배치 규칙(검증 항목)
| 규칙 | 기준 | 자동 점검 |
|---|---|---|
| 글자 | 본문 16px, 보조 13px, 최소 12px | ✔ |
| 터치 대상 | 버튼 ≥44px, 주 버튼 52px | ✔ |
| 대비 | 일반 4.5:1, 큰 글씨 3:1 (라이트·다크) | ✔ (캡션 색 교체로 통과) |
| 가로 넘침 | 360px 폭 | ✔ |
| 글씨 1.3배 | 폰 프레임 밖 넘침 없음 | ✔ |
| **하단 버튼이 본문을 가리지 않음** | 1.0·1.3배 | ✔ (이번에 **결함 발견→수정**: 고정 버튼 → 본문 아래 붙는 방식) |
| 뒤로가기·탭 이름 일치 | 문서·목업·생성기 동일 | 정독 |
### 4.3 추가된 화면(이번 요청)
- 합격 상세에 **지도 열기(네이버·카카오)·반장님께 전화·업체에 전화** 큰 버튼(SCR-H37). 비공개 현장은 합격 전 403.
- 업체 **공지 읽음 현황**(읽음/미읽음, 다시 알리기, 최대 5회, 문자는 옵트인) — SCR-C28.
- **⭐ 출연자**(저장·메모, 새 공고 먼저 알림, 출연자는 알림 끄기 가능, 무료 30명) — SCR-C29, 합격자 목록에서 "⭐ ⭐ 저장".
### 4.4 한계
목업은 HTML 시안. Flutter 실기기(iPhone Safari CanvasKit·Android) 렌더링, 키보드가 하단 버튼을 가리는 경우, TalkBack/VoiceOver, 20~40대 실사용은 구현 후 W2·W6 게이트에서 확인한다.

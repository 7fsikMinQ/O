**지금 코드를 서버에 올려도 일반 사용자를 받을 수는 없다.** 서버 구입·설정(이 문서)은 미리 해도 되지만, 아래 막힘이 풀려야 실제 오픈이다.

## 3. 도메인 구입 ★
1. 이름 후보를 정하고(예: `bojohelp.kr` 또는 `.com`) 등록 업체에서 **사용 가능 여부 조회**([16번](./16_외부사실_확인표.md): 가용성 미확인). 상표 조회(특허정보검색서비스 KIPRIS)도 한다.
2. 구매. **자동 갱신 켜기**(만료되면 서비스가 멈춘다).
3. 이 서비스는 서브도메인 3개를 쓴다(예시 — `내도메인.kr` 을 본인 것으로 바꾼다):
| 주소 | 용도 |
|---|---|
| `api.내도메인.kr` | 백엔드 서버(Lightsail) |
| `company.내도메인.kr` | 업체·관리자 웹(Cloudflare Pages) |
| `app.내도메인.kr` | 출연자 웹(PWA, iPhone 용. Cloudflare Pages) |

## 4. Cloudflare 에 도메인 연결
1. Cloudflare 대시보드 → **도메인 추가** → 무료(Free) 플랜 선택.
2. 화면에 나오는 **네임서버 2개**를 도메인 구입처의 "네임서버 변경" 메뉴에 입력한다(Cloudflare 에서 구입했다면 자동).
3. 몇 분~몇 시간 뒤 Cloudflare 에서 상태가 **활성(Active)** 이 된다.
4. **SSL/TLS → 개요 → 암호화 모드를 `Full (strict)`** 로 한다(Cloudflare↔서버 구간도 인증서 검증).
5. SSL/TLS → 엣지 인증서 → **Always Use HTTPS 켜기**, 최소 TLS 버전 1.2.
DNS 레코드(A 레코드)는 서버 IP 가 나온 뒤 §6-7 에서 넣는다.

## 5. Lightsail 서버 만들기 ★ (AWS 콘솔, 메뉴 이름은 달라질 수 있음 ◐)
1. AWS 로그인 → 검색창에 **Lightsail** → 열기. 오른쪽 위에서 지역을 **서울(ap-northeast-2)** 로 맞춘다(한국 사용자 지연 최소).
2. **인스턴스 생성**
   - 위치: 서울, 가용 영역은 기본값.
   - 플랫폼: **Linux/Unix**, 블루프린트: **운영 체제 전용(OS Only) → Ubuntu 24.04 LTS**.
   - SSH 키: 새 키 쌍을 만들어 **내려받은 `.pem` 파일을 안전한 곳에 보관**(분실하면 접속이 어렵다. 비밀번호 관리자에 파일째 보관).
   - 플랜: **2GB RAM / 2 vCPU / 60GB SSD (월 US$12)**. 인스턴스 이름 `bojohelp-prod`.
   - 생성.
3. **고정 IP**: 네트워킹 → **고정 IP 생성** → 인스턴스에 연결. (연결해 두지 않으면 재시작 때 IP 가 바뀐다.) 이 주소가 `서버IP`.
4. **방화벽**(인스턴스 → 네트워킹 → IPv4 방화벽 규칙):
   - SSH(22): **내 집/사무실 IP 로만 제한**(IP 확인: https://ifconfig.me). ⚠ 제한하면 콘솔의 "브라우저 SSH" 는 못 쓴다. IP 가 자주 바뀌면 SSH 접속 때마다 규칙을 수정한다.
   - HTTP(80), HTTPS(443): 모두 허용(Caddy 가 인증서를 받기 위해 80 이 필요).
   - **5432(DB)·8080(앱)·8025 는 절대 열지 않는다.**
5. **스냅샷 자동 백업**(인스턴스 → 스냅샷 → 자동 스냅샷 켜기): 서버 전체 복구용(추가 요금 소액). DB 덤프 백업(§9)과 별개로 둔다.

## 6. 서버 설정 (한 번만)
### 6-1. 접속
내 PC(WSL)에서:
```bash
chmod 600 ~/Downloads/LightsailDefaultKey-ap-northeast-2.pem
```
(내려받은 파일의 실제 이름·위치로 바꾼다. Windows 에 있으면 `/mnt/c/Users/<이름>/Downloads/…` 에서 `~/.ssh/` 로 복사 후 `chmod 600`.)
```bash
ssh -i ~/.ssh/lightsail.pem ubuntu@서버IP
```
처음 접속 시 `yes`. 이후 줄 앞이 `ubuntu@ip-…` 면 **서버 안**이다.

### 6-2. 운영 담당 계정 만들고 root·비밀번호 로그인 막기
서버에서(`ubuntu` 계정):
```bash
sudo adduser --disabled-password --gecos "" deploy
```
```bash
sudo usermod -aG sudo deploy && echo 'deploy ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/90-deploy
```
```bash
sudo mkdir -p /home/deploy/.ssh && sudo cp ~/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys && sudo chown -R deploy:deploy /home/deploy/.ssh && sudo chmod 700 /home/deploy/.ssh && sudo chmod 600 /home/deploy/.ssh/authorized_keys
```
**다른 창에서 `ssh -i … deploy@서버IP` 로 접속되는지 확인한 뒤에만** 다음을 한다(잘못하면 잠긴다):
```bash
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/; s/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config && sudo systemctl restart ssh
```
이후 `deploy` 계정으로 작업한다.

### 6-3. 자동 보안 업데이트·침입 차단·시간·여유 메모리
```bash
sudo apt update && sudo apt -y upgrade && sudo apt -y install unattended-upgrades fail2ban ufw git curl age rclone
```
```bash
sudo dpkg-reconfigure -plow unattended-upgrades
```
(질문에 `Yes`.) 서버 방화벽(2중 방어):
```bash
sudo ufw default deny incoming && sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw --force enable
```
2GB 서버에서 Java 빌드가 메모리 부족으로 죽지 않도록 **스왑 2GB** 를 만든다:
```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```
시간대는 UTC 로 둔다(`timedatectl` 로 확인).

### 6-4. Docker 설치
```bash
curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker deploy
```
SSH 를 한 번 끊었다 다시 접속한 뒤 `docker ps` 가 오류 없이 빈 목록을 보이면 된다.

### 6-5. 저장소 받기 (서버용 읽기 전용 열쇠)
```bash
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N "" -C "bojohelp-prod"
```
```bash
cat ~/.ssh/deploy_key.pub
```
출력 한 줄을 복사 → GitHub 저장소 **Settings → Deploy keys → Add deploy key**(제목 `prod`, **Allow write access 는 체크하지 않는다**). 그다음:
```bash
printf 'Host github.com\n  IdentityFile ~/.ssh/deploy_key\n  IdentitiesOnly yes\n' >> ~/.ssh/config && chmod 600 ~/.ssh/config
```
```bash
mkdir -p ~/app && cd ~/app && git clone git@github.com:7fsikMinQ/O.git . && git checkout main 2>/dev/null || git checkout dev/mk
```
(운영은 안정 브랜치만 받는다. `main` 은 폐쇄 베타 때 만들기로 한 브랜치이며 아직 없으면 `dev/mk` 가 쓰인다 — 25번 §1.)

### 6-6. 비밀값 만들기 (가장 중요)
서버에서 각각 **한 번씩** 만들어 값을 **비밀번호 관리자에 저장**한다(터미널 기록·메신저에 붙이지 않는다):
```bash
openssl rand -base64 32
```
이것을 아래 4번 실행해 각각 `JWT_SIGNING_KEY`, `HMAC_PEPPER`, `FIELD_ENCRYPTION_KEY_V1`, `DB_PASSWORD` 로 쓴다(`FIELD_ENCRYPTION_KEY_V1` 은 반드시 `openssl rand -base64 32` 결과 그대로 — 32바이트).
> ⛔ **`FIELD_ENCRYPTION_KEY_V1` 을 잃어버리면 저장된 주민번호·계좌를 영영 복호화할 수 없다.** 비밀번호 관리자 + 종이/금고 등 **서로 다른 2곳**에 보관한다. `HMAC_PEPPER` 를 바꾸면 기존 전화번호·주민번호 해시가 전부 무효가 되므로 **한 번 정하면 바꾸지 않는다.** 서버·백업·R2 가 같은 곳에 있지 않게 한다(서버만 잃으면 키도 같이 잃는 구조 방지).

### 6-7. `.env.prod` 만들기
```bash
cd ~/app && cp .env.prod.example .env.prod && chmod 600 .env.prod && nano .env.prod
```
(`nano`: 수정 후 `Ctrl+O` Enter 저장, `Ctrl+X` 종료.) 채울 값:
| 키 | 값 |
|---|---|
| `DB_SUPERUSER`, `DB_USER` | 둘 다 `app` (지금은 한 계정. 계정 분리는 오픈 전 개선 과제) |
| `DB_SUPERUSER_PASSWORD`, `DB_PASSWORD` | **같은 값**(`openssl` 로 만든 DB 비밀번호) |
| `BACKEND_IMAGE` | §8 에서 빌드한 이미지 이름(예 `bojohelp-backend:20261101-abc1234`) |
| `API_DOMAIN` | `api.내도메인.kr` |
| `CORS_ALLOWED_ORIGINS` | `https://company.내도메인.kr,https://app.내도메인.kr` |
| `WEB_BASE_URL` | `https://company.내도메인.kr` (메일 속 링크) |
| `SMTP_HOST`/`SMTP_PORT`/`SMTP_USERNAME`/`SMTP_PASSWORD`/`MAIL_FROM` | §7 Resend 값 |
| `ADMIN_EMAIL`/`ADMIN_PASSWORD` | 최초 관리자(첫 기동 때 1회 생성). 10자 이상 영문+숫자 |
| `JWT_SIGNING_KEY`, `HMAC_PEPPER`, `FIELD_ENCRYPTION_KEY_V1` | §6-6 에서 만든 값 |
| `FIELD_ENCRYPTION_ACTIVE_VERSION` | `1` |
| `SMS_PROVIDER` | 대행사 연결 코드가 생기면 그 값(§0 막힘 1) |
> `.env.prod` 는 git 이 무시하므로 서버에만 있다. **분실 대비로 비밀번호 관리자에 사본**을 둔다.

### 6-8. Cloudflare DNS 에 서버 연결
Cloudflare → DNS → 레코드 추가:
| 종류 | 이름 | 값 | 프록시 |
|---|---|---|---|
| A | `api` | `서버IP` | **처음에는 DNS 전용(회색 구름)** → 서버가 인증서를 받은 뒤 **프록시(주황 구름)** 로 전환 |
(처음부터 주황으로 두면 인증서 발급이 실패할 수 있다. §10 첫 기동 후 `https://api…` 가 열리면 주황으로 바꾸고 SSL 모드 `Full (strict)` 를 확인한다.)

## 7. 메일 도메인 인증 (스팸함 방지, 오픈 전 필수) ◐
1. Resend 콘솔 → **Domains → Add Domain**(`내도메인.kr`) → 지역 선택.
2. 화면에 나오는 **SPF(TXT), DKIM(CNAME/TXT), (권장) DMARC(TXT)** 레코드를 Cloudflare DNS 에 **화면 그대로** 추가한다(프록시는 꺼진 회색 구름). 값은 Resend 가 안내한 것을 그대로 쓴다.
3. Resend 에서 **Verify** → 상태 `Verified`.
4. **API Keys** 에서 키 생성 → `SMTP_PASSWORD`. SMTP 정보(`SMTP_HOST=smtp.resend.com`, `SMTP_USERNAME=resend`, 포트 587)는 Resend 문서의 현재 값을 확인해 입력한다. `MAIL_FROM` 은 인증한 도메인의 주소(예 `no-reply@내도메인.kr`).
5. 무료 한도(월 3,000·일 100통)를 넘기면 발송이 멈춘다 → 이용자가 늘면 유료 또는 Amazon SES(서울).

```bash
docker compose --env-file .env.prod -f infra/prod/docker-compose.prod.yml logs --tail 50 backend
```
`Started BojoHelpApplication` 이 보이고, 내 PC 에서 `curl -s https://api.내도메인.kr/actuator/health` 가 `UP` 이면 성공. 서버가 **죽고 다시 켜지기를 반복**하면 로그의 마지막 오류를 본다(대개 `.env.prod` 값 누락 — 운영 설정은 기본값이 없어 빠지면 일부러 기동을 멈춘다).

## 9. 백업 (서버 1대 = 백업이 곧 가용성)
### 9-1. 암호화 열쇠 만들기 (내 PC 에서, 서버 아님)
```bash
age-keygen -o backup-key.txt
```
출력의 `Public key: age1…`(공개키)만 서버에 둔다. **`backup-key.txt`(비밀키)는 서버에 절대 두지 않고** 비밀번호 관리자·금고에 보관한다(복구 때 필요). 서버에서:
```bash
mkdir -p ~/secrets && echo 'age1여기에공개키' > ~/secrets/backup.pub && sudo mkdir -p /var/backups && sudo chown deploy /var/backups
```
### 9-2. R2 버킷과 rclone
Cloudflare → R2 → 버킷 생성 `app-backup`(비공개) → **API 토큰(Object Read & Write, 이 버킷만)** 생성. 서버에서 `rclone config` 로 원격 이름 **`r2`**(종류 `s3`, 제공자 `Cloudflare`, 엔드포인트 `https://<계정ID>.r2.cloudflarestorage.com`)를 만든다.
### 9-3. 매일 자동 실행
```bash
crontab -e
```
맨 아래에 추가(DB 계정 이름은 스크립트가 `.env.prod` 에서 읽는다):
```
0 18 * * * BACKUP_AGE_RECIPIENT_FILE=/home/deploy/secrets/backup.pub bash /home/deploy/app/infra/prod/backup.sh >> /home/deploy/backup.log 2>&1
```
(서버 시간이 UTC 이므로 `0 18 * * *` = 한국 새벽 3시.) 하루 뒤 `r2:app-backup/db/` 에 `app-….dump.age`, `files/` 에 `files-….tar.age` 가 생겼는지 R2 화면에서 확인한다. 서버 안 사본은 7일, R2 사본은 R2 보존 규칙(수명 주기 규칙 90일 등)을 따로 정한다.
### 9-4. 복구 리허설 (분기마다 반드시 — 해 보지 않은 백업은 백업이 아니다)
내 PC(비밀키 보유)에서, 운영이 아닌 **임시 DB** 에 복구해 테이블 수를 확인한다:
```bash
rclone copy r2:app-backup/db/ ./restore/ && ls restore
```
```bash
age -d -i backup-key.txt restore/app-날짜.dump.age > restore/app.dump
```
```bash
docker run -d --name restore-test -e POSTGRES_PASSWORD=x -p 55432:5432 postgres:18 && sleep 8 && docker exec -i restore-test createdb -U postgres app && docker exec -i restore-test pg_restore -U postgres -d app < restore/app.dump && docker exec -i restore-test psql -U postgres -d app -c "select count(*) from users;"
```
오류 없이 사용자 수가 나오면 성공. 끝나면 `docker rm -f restore-test` 와 `restore/` 폴더 삭제(개인정보 포함).

## 10. 화면(웹) 배포 — Cloudflare Pages (화면이 만들어진 뒤)

## 12. 업데이트(배포)와 되돌리기
**업데이트**:
```bash
cd ~/app && git pull && TAG=bojohelp-backend:$(date -u +%Y%m%d)-$(git rev-parse --short HEAD) && docker build -t $TAG backend && sed -i "s|^BACKEND_IMAGE=.*|BACKEND_IMAGE=$TAG|" .env.prod && docker compose --env-file .env.prod -f infra/prod/docker-compose.prod.yml up -d backend
```
DB 테이블 변경은 서버가 시작될 때 Flyway 가 새 버전만 자동 적용한다(**배포 직전 백업 1회 수동 실행**: `BACKUP_AGE_RECIPIENT_FILE=~/secrets/backup.pub bash ~/app/infra/prod/backup.sh`). 첫 운영 배포 이후 V1 파일은 수정 금지, 변경은 V2 이후 새 파일([CLAUDE.md §5](../CLAUDE.md)).
**되돌리기**: `.env.prod` 의 `BACKEND_IMAGE` 를 직전 태그로 바꾸고 같은 `up -d backend`. (`docker images | grep bojohelp` 로 이전 태그 확인. DB 변경이 들어간 버전은 단순 롤백이 안 될 수 있으므로 그 경우 백업 복구 절차.)
**디스크 정리**(월 1회): `docker image prune -a --filter "until=720h"`.

## 13. 장애 대응 빠른 표
| 증상 | 확인 | 조치 |

## 14. 이 문서에서 아직 확인되지 않은 것 (정직한 목록)
- Lightsail·Cloudflare·Resend 콘솔의 정확한 메뉴 이름·가격은 2차 자료 기준(◐). 결제 전 화면 확인.
- §8 의 이미지 빌드·§6 의 서버 명령은 **실제 서버에서 실행해 보지 않았다**(이 환경에는 서버가 없다). 명령 문법·환경변수 이름·compose 설정은 저장소에서 자동 점검했다(26번 이후 검토 기록). 첫 설정 때 막히면 실제 오류 문구로 질문해 이 문서를 고친다.
- 문자 대행사 연결·R2 파일 어댑터·TOTP·Turnstile·계정 분리(DB 마이그레이션용/앱용)는 아직 구현 전이다.

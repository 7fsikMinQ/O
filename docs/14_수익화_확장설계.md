# 14. 수익화 · 확장 설계

> v1.1 · 2026-10-28 · **현재는 전 기능 무료, 수수료 0원.** 사용자 확정: 구독은 **업체만**, 지원자의 추가 정보 확인 기능에 월 정액(금액 추후). 인재 검색·긴급 공고·상단 노출은 추후 유료 후보. 이 문서는 "나중에 돈 벌고 싶을 때 스키마·코드를 뜯지 않도록" 구조를 정의한다. 가격·전환율 수치는 **검증이 필요한 가설**이다.

## 1. 원칙
1. **무료 가치 먼저**: 출연자는 영구 무료. 업체의 핵심 흐름(공고 → 지원 → 합격 → 현장 관리)은 무료로 두고, **규모·편의·노출·메시지 비용**에서 과금한다.
2. **스위치 하나**: `app_settings.subscription_enforcement=false` 동안은 모든 게이트가 열려 있다. 값을 `true` 로 바꾸고 플랜을 채우면 과금 모드가 된다.
3. **게이트는 한 곳**: `EntitlementService.check(company, featureCode)` 만 호출(코드 곳곳에 플랜 이름 하드코딩 금지).
4. **신규 유료 기능 = 행 추가**: `plan_features` 에 `feature_code` 를 넣고 호출 지점에서 check. 컬럼·테이블 추가 불필요.
5. **사용량은 항상 집계**: 무료 기간에도 `usage_counters` 에 쌓아 두면 가격 책정 근거가 된다.
6. **공정성**: 자사(운영자 겸 업체)도 동일 가격표·동일 규칙(13번 §6). 기존 무료 기능을 유료로 바꿀 때는 사전 공지(권장 30일 이상)와 약관 개정 동의를 거친다.

## 2. 수익 모델 (사용자 확정 + 후보)
| # | 모델 | 대상 | 게이트/구조 | 시점 | 상태 |
|---|---|---|---|---|---|
| 1 | **지원자 추가 정보 확인 구독**(타 공고 지원 목록 등) | 업체 | `plan_features.VIEW_ACTOR_APPLICATIONS` | 사용자 기반 형성 후 | **사용자 확정**, 월 정액 금액 추후(메모상 "900~1900" 단위는 확인 필요) |
| 2 | 인재 검색 | 업체 | `plan_features.TALENT_SEARCH` | 추후 | 사용자 확정(설계만) — `is_searchable` 동의자만 |
| 3 | 긴급 공고 상단 노출 | 업체 | `plan_features.URGENT_TOP` 또는 `promotions` | 추후 | 사용자 확정(설계만) |
| 4 | 상단 노출(일반) | 업체 | `promotions.FEATURED` | 추후 | 사용자 확정(설계만) |
| 5 | 알림톡/SMS 크레딧(종량) | 업체 | `credit_wallets/credit_transactions` | P3 | 후보 |

- **출연자에게는 과금하지 않는다**(구독은 업체만).
- 현재 `긴급`(is_urgent) 표시와 상단 정렬은 무료. 유료화 시 상단 고정 권한을 `URGENT_TOP` 로 게이트한다.

## 3. 플랜 구조 예시 (가설, 숫자는 시장 검증 후 확정)
| 기능 코드 | 설명 | FREE | PRO(예시) |
|---|---|---|---|
| `VIEW_ACTOR_APPLICATIONS` | 지원자의 타 공고 지원 현황 | ✕ (무료 개방 스위치로 현재는 허용) | ○ |
| `ROSTER_EXCEL_EXPORT` | 인원 정보표 엑셀 | ○ | ○ |
| `BROADCAST_MONTHLY` | 월 단체 메시지 건수 | 300 | 5,000 |
| `MEMBER_LIMIT` | 업체 직원 계정 수 | 3 | 20 |
| `HISTORY_DEPTH` | 지원자 이력 조회 건수 | 50 | 무제한 |
> 초기 시드에서 PRO 는 **비활성 플레이스홀더**(가격 0)이다. 가격을 임의로 확정하지 않는다.

## 4. 게이트 동작 (의사코드)
```text
check(company, feature):
  if setting('subscription_enforcement') == false: return ALLOW
  if setting('free_open_' + feature) == true:      return ALLOW        # 기능별 무료 개방
  plan = activeSubscription(company).plan ?? FREE
  f = plan_features[plan, feature]
  if f is null or !f.enabled:                      return DENY(PLAN_REQUIRED)
  if f.limit_value != null and usage(company, feature, thisMonth) >= f.limit_value: return DENY(LIMIT_EXCEEDED)
  return ALLOW
after success: usage_counters.used_count += 1   # 집계는 enforcement 와 무관하게 항상
```

## 5. 결제 도입 설계 (P3) — DDL 초안: `db/future/monetization_draft.sql`
| 구성 | 테이블 | 비고 |
|---|---|---|
| 결제수단 | `billing_accounts` | PG 빌링키는 앱 암호화, 카드는 last4 만 보관 |
| 청구 | `subscription_invoices` | 기간별 1건, `(subscription_id, period_start)` 유일 |
| 거래 원장 | `payment_transactions` | `pg_payment_key`, `idempotency_key` 유일(이중 결제 방지), 원응답 JSONB |
| 크레딧 | `credit_wallets` + `credit_transactions` | 잔액 = 원장 합계, 대조 배치 |
| 노출 | `promotions` | 기간 겹침 정책은 서비스에서 |
| 쿠폰 | `coupons`, `coupon_redemptions` | 체험·할인 |
- PG: 정기결제(빌링)를 지원하는 국내 PG/결제 대행(토스페이먼츠, 포트원 등) 중 심사 조건·수수료 비교 후 선택. **사업자 등록, 통신판매업 신고 여부, 부가세·전자세금계산서(B2B)** 를 세무사와 확인.
- 웹훅은 서명 검증 + 멱등 처리, 결제 성공은 PG 조회로 재확인 후 구독 활성화.
- 구독 만료/실패: 유예기간(예: 3~7일) → 기능 제한(데이터는 보존), 사전 알림.
- 환불·해지 정책을 약관에 명시(청약철회 규정 확인).

| 단계 | 내용 | 완료 기준 |

## 7. 측정 지표
- 업체: WAU, 공고 수/업체, 합격 처리 시간, 단체 메시지 사용량, 재방문율, 무료 한도 도달율.
- 전환: 한도 도달 → 업그레이드 클릭 → 결제 성공 퍼널, 해지율(churn).
- 건전성: 출연자 성실도 분포, 노쇼율 변화(플랫폼 가치), 지원자 대비 합격률.

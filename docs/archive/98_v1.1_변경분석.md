# 98. v1.1 변경 분석 — 사용자 답변 50문항 반영과 v1.0 대비 결정

> 2026-10-28. 사용자가 답한 50개 질문(+이전 제안 v1.0)을 v1.0 설계와 대조해 **무엇이 바뀌었고, 왜 그렇게 해석했으며, 어디에 위험이 있는지** 정리한다. v1.0 기록은 `archive/` 참조.

## 1. 가장 큰 변화 7가지
| # | v1.0 | v1.1 | 영향 |
|---|---|---|---|
| 1 | 업체 합격 = 확정, 예비합격·선착순 있음 | **합격 통보(SELECTED) → 출연자 확정(CONFIRMED)** 2단계. 예비합격·선착순·불합격 사유 **삭제** | 상태 머신, 정원(`selected_count`+`confirmed_count`), 만료 배치 |
| 2 | 시간 겹침 확정은 DB가 **무조건 차단** | 출연자가 경고를 확인하고 **둘 다 확정 가능**, 양쪽 업체 알림 + **확인할 때까지 1시간마다 경고** | `conflict_override`, `schedule_conflicts`, `requires_ack`, 반복 배치 |
| 3 | 하루 단위 일정(`shoot_date`, `call_time`) | **연속 구간 1시간~7일**(자정 넘김·2박3일·5박6일), 출결은 날짜별 | `job_schedules.start_at/end_at`, 생성 날짜, `attendances` 날짜별 |
| 4 | 일당/시급 혼합, 식대·연장 필드 | **시급제 + 연도별 최저시급**, 9시간 이내 8시간분 고정, 식대 등은 비고 | `minimum_wages`, `wage_mode`, `pay_note` |
| 5 | 주민번호 기본 비수집, 계좌 90일 파기 | **주민번호 필수·계좌·서명·증빙 전부 보관** | `actor_tax_identities`(HMAC·버전), 서명 메타·해시, 보존기간 설정 — **법적 위험 상승** |
| 6 | 출석은 반장 수기, 참석 확인 전날 18~22시 | **인원별 QR 출퇴근**(팀장이 세션 열어야 활성), 참석 확인 **집합 2시간 전~30분 전** | `attendance_sessions`, 회전 토큰, 5분 배치 |
| 7 | 출연자 앱 우선(Flutter) | **앱 + 웹**, Android 우선·**iPhone 은 웹(PWA)**, 다크 모드, 파스텔 | Flutter 1벌(앱+웹), 푸시 한계 폴백, 토큰 개편 |

## 4. 위험과 권고
1. **주민번호 수집·보관 + 증빙 전부 보관**은 개인정보보호법상 가장 민감한 선택이다. 법령 근거(원천징수 의무자는 업체), 수탁 구조, 암호화·접근통제·보존기간을 **오픈 전 반드시 전문가와 확정**해야 한다. 완화책으로 (C) 정산 시점에 업체가 별도 수집하는 방식을 `require_rrn_before_apply=false` 로 전환할 수 있다.
2. **3개월 전부는 무리**. MVP 컷(10번 §9)으로 12주 폐쇄 베타를 권고. 정산·은행 양식·원천징수는 오픈 후.
3. iPhone 웹 푸시는 제약이 있어 **중요 알림 폴백**(앱 내 배너, 추후 알림톡)이 필요하다.
4. 패널티·노쇼 공개는 명예훼손 소지가 있어 **횟수만, 소명·무효화 경로** 유지.
5. 은행별 대량이체 양식은 실제 양식 파일을 받아야 정확히 만들 수 있다.

## 5. v1.0 대비 정리 (유지 / 변경 / 삭제)
- **유지**: 모듈러 모놀리스, PostgreSQL, 아웃박스, R2, RBAC·다형성 첨부·게시판 분리, 구독 구조, 점검 도구 체계.
- **변경**: 일정·상태·정원·공개 범위·참석 확인·출결·정산 계산·디자인 토큰·클라이언트 구성.
- **삭제**: 예비합격(`WAITLISTED`)·보류(`SHORTLISTED`)·선착순·불합격 사유·성실도 점수·계좌 90일 파기·셔틀 구분·식대/교통 컬럼·GPS 체크인.

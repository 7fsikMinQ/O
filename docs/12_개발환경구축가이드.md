# 12. 개발 환경 구축 가이드 (v1.3 — 노트북 WSL2 기준)

> v1.0 · 2026-10-28 · 버전은 **착수 시점의 최신 LTS/stable** 로 맞춘다(아래는 목표).

## 0. 내 노트북(Windows + WSL2)에서 개발하기 — 개발 DB 는 로컬
**원칙: 개발 DB·MinIO·Mailpit 은 전부 노트북 안에서만 돈다. 외부에 포트를 열지 않고(포트포워딩 ✕), 운영 데이터는 복사하지 않는다.**

| 항목 | 권장 | 이유·주의 |
|---|---|---|
| Windows | 11 22H2 이상 | WSL2 *mirrored networking* 지원(폰·에뮬레이터에서 localhost 접근 편함) |
| WSL | WSL2 + Ubuntu 24.04 | `wsl --install -d Ubuntu-24.04` |
| 프로젝트 위치 | **WSL 리눅스 홈(`~/work/…`)** | `/mnt/c/...` 는 파일 I/O 가 매우 느림, 줄바꿈·권한 문제 |
| Docker | WSL 안에 **Docker Engine** 설치 (또는 Docker Desktop) | Docker Desktop 은 기업 규모에 따라 유료 라이선스(조건 ❓ 확인), 개인 개발은 Engine 이 단순·무료 |
| DB | `docker compose up` 의 PostgreSQL(운영과 같은 메이저 버전 권장, compose 는 18 이미지, 포트는 127.0.0.1 에만 바인딩) | 데이터 볼륨은 WSL 리눅스 파일시스템(named volume) |
| 백엔드 | WSL 안에 JDK 25(sdkman) + Gradle/Maven wrapper | |
| 웹 | WSL 안에 Node LTS + pnpm | Vite dev 서버 `--host` 로 폰 접속 가능 |
| Flutter | **Windows 쪽에 Flutter SDK + Android Studio** 권장 | Android 에뮬레이터/USB 디버깅은 Windows 에서 훨씬 안정. WSL 에서는 `flutter build web` 위주. 정말 WSL 에서 하려면 Android SDK 를 Windows 에 두고 `adb` 를 무선(`adb tcpip`) 연결 |
| 폰 테스트 | 같은 Wi-Fi + mirrored networking, 또는 `cloudflared tunnel --url http://localhost:8080` 임시 URL | **공유기 포트포워딩 ✕**, 테스트가 끝나면 터널 종료 |
| 메모리 | `%UserProfile%\.wslconfig`: `[wsl2] memory=8GB` `processors=4` `networkingMode=mirrored` | 노트북 RAM 의 절반 정도 |
| IDE | IntelliJ(WSL 프로젝트 지원) 또는 VS Code + *WSL* 확장 | |
| 백업 | 중요 설계 파일은 Git push. 로컬 DB 는 개발용이라 날려도 되게 시드로 복원 | |

```bash
# WSL Ubuntu 최초 1회
sudo apt update && sudo apt install -y git curl unzip postgresql-client
curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER   # 재로그인 필요
mkdir -p ~/work && cd ~/work && git clone <저장소>
```
- 로컬 DB 에는 `tools/test_schema.sql` 이 쓰는 가짜 데이터만 넣는다. 실제 이름·주민번호·계좌는 개발 DB 에 넣지 않는다.
- 운영 서버 구성은 [18번](./18_운영서버_보안_가이드.md).

## 2. 저장소 구조 (모노레포)
```text
.
├─ CLAUDE.md                  # 프로젝트 기억·작업 지침 (AI 세션용)
├─ docs/                      # 설계 문서 (00~30)
├─ tools/                     # 문서 생성·검증 (build_docs.py, spec/, test_schema.sql)
├─ db/
│  ├─ schema.sql              # 전체 스키마 (단일 진실 원천, 문서 생성에 사용)
│  ├─ migration/              # Flyway V1__, V2__ ... (schema.sql 을 단계 분할)
│  └─ future/                 # 아직 적용하지 않는 확장 DDL 초안 (수익화 등)
├─ backend/                   # Spring Boot (Gradle 멀티모듈 or 단일 모듈+패키지 분리)
├─ web/                       # React + Vite (업체·관리자)
├─ app/                       # Flutter (출연자 + 현장 모드; Android 앱 + 웹/PWA 동일 코드)
├─ infra/                     # docker-compose.dev.yml, 배포용 compose, nginx 설정
└─ .env.example
```

### 3.1 백엔드
```bash
cd backend
./gradlew bootRun --args='--spring.profiles.active=local'     # http://localhost:8080
./gradlew test                                                 # Testcontainers(PostgreSQL) 통합 테스트
```
- `application-local.yml` 은 `.env` 값을 읽는다. `spring.jpa.hibernate.ddl-auto=validate` (스키마는 Flyway/SQL 이 소유, JPA 가 생성 금지).
- 시간대: `spring.jackson.time-zone=UTC`, `hibernate.jdbc.time_zone=UTC`.
- Spring Boot 4 는 3.x 와 의존성 구성이 다르다(마이그레이션 가이드 참조). 필수 의존성(요약): web, security, data-jpa, validation, actuator, flyway-core + flyway-database-postgresql, postgresql, querydsl, jjwt, springdoc-openapi, shedlock-spring + jdbc provider, apache-poi, aws-sdk-v2 s3, firebase-admin, testcontainers.
- 필수 코드 규칙: 모든 엔드포인트 권한 명시, 엔티티 직접 반환 금지, 민감정보 로그 금지, `Idempotency-Key` 처리, 확정 서비스는 03 부록 E 순서.

### 3.3 앱 (Flutter) — Android 앱 + iPhone 용 웹(PWA)
> **Flutter 3.44 부터 SDK 의 Material/Cupertino 는 동결되고 `material_ui`/`cupertino_ui` 패키지로 분리**됐다(2026-11 stable 에서 SDK 쪽 공식 deprecate 예정). 프로젝트 시작부터 패키지를 사용해 이후 마이그레이션 비용을 없앤다(`flutter pub add material_ui cupertino_ui`).
```bash
cd app && flutter pub get
dart run build_runner build --delete-conflicting-outputs     # freezed/json 생성
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080/api/v1      # 안드로이드 에뮬레이터
flutter test
flutter build web --release            # iPhone Safari/PWA 용 기본(CanvasKit) 빌드. Wasm 빌드는 iOS 브라우저에서 동작하지 않음(공식 문서) → iPhone 대상에 쓰지 말 것
```
- 웹 빌드 주의: 이미지 CORS(R2 버킷 CORS 설정), 카메라/파일 선택, 서명 패드, QR 표시는 웹에서도 동작하나 **QR 스캔은 반장용 Android 앱 기준**. iOS Safari 푸시는 홈 화면 추가(PWA) 시에만 가능.
- Firebase: 콘솔에서 프로젝트 생성 → Android/iOS 앱 등록 → `google-services.json`/`GoogleService-Info.plist` 배치(커밋 금지) → FCM 서비스 계정 키는 서버 시크릿으로.
- 카카오 로그인: Kakao Developers 앱 등록 → 네이티브 앱 키·플랫폼 키 해시 등록.
- 애플 로그인: Apple Developer 에서 Sign in with Apple 활성화(iOS 출시 시 필수).
- 폰트: Pretendard(SIL OFL) + 이모지용 Noto Color Emoji 서브셋을 `assets/fonts` 에 포함(웹에서 이모지 일관성, 15번 문서).

### 3.4 Cloudflare 설정 (운영/스테이징)
1. 도메인 DNS 를 Cloudflare 로 이전.
2. R2 버킷 2개(`private`, `public`) 생성, API 토큰(해당 버킷만) 발급, `public` 은 커스텀 도메인 연결 + CDN 캐시.
3. Pages 프로젝트에 `web/` 연결(빌드 `pnpm build`, 출력 `dist`).
4. Turnstile 사이트 키/시크릿 발급.
5. WAF 기본 관리 규칙·봇 방어 켜기.

## 7. 자주 겪는 문제
- **`Migration checksum mismatch for migration version 1` 로 서버가 안 뜰 때**: 첫 운영 배포 전에는 `V1__baseline.sql` 을 schema.sql 과 맞춰 다시 만들 수 있어서(CLAUDE.md §5-8) 이미 V1 이 적용된 개발 DB 와 어긋난다. `tools/dev/reset-db.sh` 로 개발 DB 를 비우고 다시 시작한다(개발 DB 전용, 운영 ✕).
- **Maven Central 429(Too Many Requests)**: 공용 IP 에서 repo.maven.apache.org 가 제한될 때 `~/.gradle/init.d/mirror.gradle` 로 Google 미러(`https://maven-central.storage-download.googleapis.com/maven2`)를 먼저 쓰게 한다(저장소에는 넣지 않음).
- 백엔드를 JDK 21 로만 돌려 볼 때: `./gradlew test -PjavaVersion=21` (운영·CI 는 25).
| 증상 | 원인/해결 |
|---|---|
| 안드로이드 에뮬레이터에서 API 접속 불가 | `localhost` 대신 `10.0.2.2` |
| EXCLUDE 제약 생성 오류 | `CREATE EXTENSION btree_gist` 필요(관리형 DB 는 허용 확장 목록 확인) |
| 서명 URL 403 | 서버·스토리지 시계 오차, 버킷 CORS 에 `PUT` 허용 |
| 한글 파일명 깨짐 | 업로드 키는 UUID, 원본명은 `original_name` 에만 |
| iPhone 웹 푸시 미수신 | 홈 화면에 추가(PWA) 후 알림 허용 필요, iOS 16.4+ |
| Flutter 웹 이미지 안 보임 | R2 버킷 CORS(`GET`) 및 CDN 헤더 확인 |
| Flyway 체크섬 오류 | 적용된 마이그레이션 수정 금지 → 새 버전 추가 |

# 02. 프로세스 정의서 (v1.1)

> 2026-10-28 · 사용자 답변 50문항 반영. 요구사항(01)·기능(03)과 ID 로 연결. 다이어그램은 Mermaid.
> 용어: 업체, 출연자, 반장(`FIELD_LEADER`), 팀장(`MANAGER`), 스케줄러(`SCHEDULER`, 업체당 1~4명), 시스템=서버/배치.

## 목차
1. 가입·업체 승인 / 2. 공고 등록·게시 / 3. 탐색·지원(현재 사진·서명) / 4. 선발: 합격 통보 → 출연자 확정 / 5. 복수 확정 충돌 / 6. 마감 자동 불합격 · 마감 후 추가 합격 / 7. 합격 이후: 메시지·인원표·정보표 / 8. 참석 확인 → QR 출퇴근 / 9. 확정 후 취소와 패널티 판정 / 10. 일정 취소·연기 / 11. 정산 / 12. 알림 파이프라인 / 13. 증빙 보관·파기 / 14. 구독 게이트

## 1. 가입 · 업체 승인 (REQ-A01~A08, C01, M01)
```mermaid
flowchart TD
  A["앱/웹 진입 (Android 앱 · iPhone 웹)"] --> B{"가입 유형"}
  B -->|출연자| C["휴대폰 문자 숫자 6자리 + 약관(서비스·개인정보·제3자 제공) 동의"]
  B -->|업체| D["이메일/카카오 가입 + 약관 동의"]
  C --> E["프로필: 신체·사이즈·집주소·머리·문신·사진 + 기본 계좌·집합지"]
  E --> F{"만 19세 미만?"}
  F -->|예| G["현재 지원 불가 안내 (동의서 흐름은 비활성)"]
  F -->|아니오| H["주민등록번호 등록 (고유식별정보 동의, 첫 지원 전 필수)"]
  H --> I["지원 가능"]
  D --> D2["확인 메일 링크로 이메일 소유 확인 (24시간, 1회용)"]
  D2 --> J["업체 등록: 사업자번호·대표자·등록증 업로드"]
  J --> K["companies=PENDING"]
  K --> L["관리자 서류 검토"]
  L -->|승인| M["APPROVED → 공고 게시 가능 + 직원 초대·직책(스케줄러 1~4명 지정)"]
  L -->|반려| N["사유 안내 → 재제출"]
```
| 단계 | 담당 | 입력 → 출력 | 예외/규칙 |
|---|---|---|---|
| 가입·로그인(출연자) | 출연자 | 휴대폰 번호 → 문자 숫자 6자리 → `users`(이메일 없이 가능), `otp_challenges`, 약관 → `user_consents`. 로그인은 90일 유지 | 중복 번호 409, 시도 10회·재전송 제한 |
| 가입·로그인(업체·관리자) | 업체·관리자 | 이메일·비밀번호·약관 → 확인 메일 발송(아웃박스) → 링크로 이메일 확인 → 확인 후에만 업체 등록·직원 초대 수락 → 관리자 승인 | 중복 이메일 409, 5회 실패 시 그 IP 만 15분 잠금+주인에게 알림 메일, 확인 메일 재발송 1분 1회·하루 5회 |
| 비밀번호 재설정 | 업체·관리자 | 이메일 입력 → 임시 비밀번호 메일(30분) → 임시 비밀번호로 로그인(제한 토큰) → 새 비밀번호 설정(SCR-AU13) → 전 기기 로그아웃·알림 메일 | 계정 유무와 무관하게 항상 202, 한도 초과는 조용히 미발송 |
| 번호 인증 | 출연자 | 가입 시 문자 인증이 곧 `phone_verified_at` (카카오 전화번호 동의항목은 심사 통과 시 병행) | 번호 유일 |
| 주민번호 등록 | 출연자 | 번호 입력 → 형식·생년월일·성별 일치 검증 → 암호화 저장 + HMAC 해시 | 이미 활성인 동일 번호가 있으면 **중복 가입 의심**(409), 화면에는 항상 마스킹 |
| 업체 등록·승인 | 업체·관리자 | 등록증 → `companies`, `company_verifications` | 미승인 업체는 공고 게시 403 |

## 2. 공고 등록 · 게시 (REQ-J01~J10)
```mermaid
flowchart TD
  A["업체 직원: 공고 작성"] --> B["제목은 가제 (비공개 현장 기본값 ON)"]
  B --> C["일정 추가 N: 시작~종료 (1시간~21일(3주), 자정 넘김·숙박 가능), 집합지, 담당 반장"]
  C --> D["일정별 역할 N: 인원, 필수 요건(성별·출생연도·키·몸무게·머리·문신), 시급 (최저시급 or 직접), 비고, 의상"]
  D --> E{"임시저장?"}
  E -->|예| F["DRAFT"]
  E -->|게시| G{"업체 APPROVED 이고 검증 통과? (일정 길이·최저시급 연도·필수값)"}
  G -->|아니오| H["오류 안내"]
  G -->|예| I["OPEN + JOB_PUBLISHED"]
```
- 시급에서 **'최저시급' 선택 시** `minimum_wages` 에서 해당 연도 값을 자동 채우고 공고에 스냅샷(`hourly_wage_krw`, `min_wage_year`). 안내 문구: "9시간 이내 근무는 최저시급×8시간 고정".
- 식대(아침·점심·저녁)·교통 등은 **비고에 자유 기재**(필터 대상 아님).
- **공고 복사**: 일정·역할 구조를 새 DRAFT 로 복사(지원자·확정자 제외).
- **수정 제한**: 지원자가 있는 역할의 정원 감소/삭제 거부(409), 조건 변경 시 합격 통보를 받은 사람에게 변경 알림.

## 3. 탐색 · 지원 (REQ-S01~S05, AP01~AP06)
```mermaid
sequenceDiagram
  actor U as 출연자(앱/웹)
  participant API as 서버
  participant DB as DB
  U->>API: GET /jobs/calendar, /jobs (필터)
  API-->>U: 달력(다일 일정은 걸친 날짜 모두)/목록
  U->>API: GET /positions/{id}/apply-form
  API->>DB: 프로필·계좌·주민번호 등록·필수 요건·겹침 조회
  API-->>U: 자동 입력값 + 자격 판정(사유 목록) + 필요한 사진·서명 + 겹침 경고(차단 아님)
  U->>API: 현재 사진 업로드(presign→직접 업로드→complete) + 서명 이미지 업로드
  U->>API: POST /positions/{id}/applications (Idempotency-Key)
  API->>DB: 자격 재검증 → 스냅샷·해시·IP/기기·사진·서명 저장 (APPLIED)
  API->>DB: 상태이력 + outbox(APPLICATION_SUBMITTED)
  API-->>U: 201
```
- 지원 시 **프로필에서 자동 입력**: 이름·번호·성별·출생연도·키·몸무게·사이즈·집주소·집합지·계좌. 계좌는 "내 정보에서 가져오기" 또는 "다른 계좌 입력(은행·계좌번호·예금주)". 주민번호는 화면에 입력하지 않고 등록된 최신 버전을 **참조**한다.
- **현재 사진 필수**, **전자서명 필수**. 서명은 서명 이미지·시각·IP·기기·약관 버전·무결성 해시(`snapshot_hash`)로 증빙.
- **같은 날/겹치는 일정에도 지원 가능**(경고만). 미성년자(만 19세 미만)는 현재 지원 불가.
- 자격 판정 순서·사유 코드: 03 부록 D.

## 4. 선발 — 합격 통보 → 출연자 확정 (REQ-SEL01~SEL06, SEL09, PC01~PC02)
```mermaid
flowchart TD
  A["업체: 지원자 카드/그리드 (휴대폰 지원 단계부터 공개)"] --> B["상세: 프로필·현재 사진·역대 합격 이력·타 공고 지원*·노쇼/패널티 횟수·겹침 배지"]
  B --> C{"결정"}
  C -->|합격 통보| D["정원 확인 selected+confirmed < 정원 → SELECTED, 응답 기한 설정, 집주소·계좌 등 합격 정보 공개"]
  C -->|불합격| E["REJECTED (사유 없음)"]
  D --> F["출연자 알림: 합격했어요 (확정 기한)"]
  F --> G{"출연자 응답"}
  G -->|확정| H["CONFIRMED: selected-1, confirmed+1 → 인원 충족"]
  G -->|어렵겠어요| I["CANCELED_BY_ACTOR (패널티 없음), 정원 해제"]
  G -->|무응답| J["기한 경과 EXPIRED, 정원 해제, 업체 알림"]
  H -->|겹치는 확정 존재| K["경고 시트 → 5장 충돌 처리"]
```
\* 타 공고 지원 열람은 `subscription_enforcement=false` 이거나 `free_open_application_history=true` 일 때 무료, 아니면 구독 기능 필요. 타 업체 공고는 제목 대신 시간대·상태만 보인다.
- **예비합격·선착순·불합격 사유는 없다.** 업체가 보고 뽑는다.
- 합격 통보 시점에 같은 사람의 다른 SELECTED/CONFIRMED 와 시간이 겹치면 업체 화면에 **겹침 경고 배지**(차단 아님). 최종 충돌 처리는 출연자 확정 단계.
- 일괄 처리는 건별 성공/실패를 가려 **207**.

## 5. 복수 확정 충돌 (REQ-SEL10, N07)
```mermaid
flowchart TD
  A["출연자 [확정] 클릭"] --> B{"예약 구간이 다른 CONFIRMED 와 겹침?"}
  B -->|아니오| C["CONFIRMED"]
  B -->|예| D["409 TIME_CONFLICT + 충돌 목록"]
  D --> E["앱 경고 시트: ① 취소하고 다른 곳 선택 ② 그래도 둘 다 확정"]
  E -->|①| F["선택한 쪽 취소"]
  E -->|②| G["proceedDespiteConflict=true → conflict_override CONFIRMED + schedule_conflicts"]
  G --> H["양쪽 업체: 알림 + 메시지 (겹치는 두 건 안내)"]
  G --> I["출연자: 확인 필요 알림 (requires_ack)"]
  I --> J{"확인(ack) 또는 한쪽 취소?"}
  J -->|아니오| K["ConflictReminder: 60분마다 재알림"]
  K --> J
  J -->|예| L["반복 중지 (업체 화면 충돌 배지는 유지)"]
```
- 의도 없는 동시 확정(경쟁 조건)은 DB `EXCLUDE` 가 막고, **경고를 확인하고 진행한 확정만** `conflict_override` 로 허용한다.

## 6. 마감 · 자동 불합격 · 마감 후 추가 합격 (REQ-SEL05, SEL11, J08)
```mermaid
flowchart TD
  A["트리거: ①업체 마감 ②지원 마감시각 ③집합 시각 경과 배치(5분)"] --> B["APPLIED → AUTO_REJECTED (+묶음 안내 알림)"]
  B --> C["공고는 CLOSED 이지만 '이전 공고 보기 → 지원자 보기'로 계속 열람"]
  C --> D["후보 산출: 일정 ±1일에 SELECTED/CONFIRMED 가 없는 지원자 = 가용"]
  D --> E["업체가 가용 지원자에게 메시지/알림 (CLOSED_AVAILABLE 또는 직접 선택)"]
  E --> F["출연자 답장 확인"]
  F --> G["합격 통보 SELECT (정원 여유 시) → 출연자 확정"]
```
- 정원에 여유가 없으면 `FULL`. 마감 해제(`reopen`)도 가능.
- 가용 판단은 **자동 확정이 아니라 후보 제시**이며 최종 선택은 업체가 한다.

## 7. 합격 이후 — 메시지 · 인원표 · 인원 정보표 (REQ-PC03~PC05, PC13)
```mermaid
sequenceDiagram
  actor C as 업체/반장
  participant API as 서버
  participant OB as outbox 워커
  actor A as 수신 출연자들
  C->>API: POST /company/broadcasts {대상,제목,내용,채널}
  API->>API: 권한(담당 일정)·월 한도(entitlement) 확인
  API->>API: job_broadcasts + 수신자별 message_threads/messages + job_broadcast_recipients
  API->>OB: outbox(MESSAGE_RECEIVED) 같은 트랜잭션
  API-->>C: 202 {recipientCount}
  OB->>A: 인앱 알림 + FCM 푸시
  A->>API: 열람(읽음) / 답장 POST /me/messages/threads/{id}/reply
  C->>API: GET /company/messages/threads → 답장 확인
```
- 대상: 확정자 전체 / 통보자 포함 / 참석 미확인 / 마감 후 가용 지원자 / 직접 선택. **출연자는 먼저 보낼 수 없고 답장만** 가능.
- **인원표**: 일정·역할별 정원/지원/통보/확정/참석확인/출석/노쇼. **인원 정보표**: 이름·번호·성별·출생연도·키·몸무게·사이즈·집주소·집합지·계좌·주민번호(마스킹) — 직책별 공개 범위(03 부록 B), 엑셀은 암호화, 모든 열람·다운로드 감사.
- 합격 이후 출연자는 업체/반장 번호를, 업체는 출연자 번호를 확인해 전화·문자할 수 있다.

## 8. 참석 확인 → QR 출퇴근 (REQ-PC06, PC07, PC08)
```mermaid
flowchart TD
  A["집합 2시간 전 (5분 배치)"] --> B["확정자 전원에 참석 확인 푸시"]
  B --> C{"집합 30분 전까지 응답?"}
  C -->|응답| D["departure_confirmed_at"]
  C -->|무응답| E["담당 반장/업체에 미응답자 알림 → 전화·문자"]
  D --> F["현장: 팀장/반장이 [출근 열기] (세션)"]
  E --> F
  F --> G["출연자 앱에 본인 전용 QR 활성 (30초마다 변경)"]
  G --> H["반장 앱이 QR 스캔 → 서버 검증 → attendances(날짜별) 기록"]
  H --> I["[출근 닫기] ... 종료 시 [퇴근 열기]→스캔→[퇴근 닫기]"]
  I --> J["근무분 계산 → 9시간 이내 8시간 고정 / 초과 시 시급×시간"]
  H --> K{"미체크 → 수기 보정(감사) 또는 NO_SHOW"}
  K --> L["NO_SHOW: 노쇼 횟수 +1 (공고당 1건, 점수제 없음)"]
```
- 세션이 닫혀 있으면 QR 이 없고, 스크린샷은 30초 후 무효 → **대리 출석 방지**.
- 숙박 등 다일 일정은 날짜별 세션·출결.

## 9. 확정 후 취소와 패널티 판정 (REQ-PC09, C06)

```mermaid
flowchart TD
```

## 10. 일정 취소 · 연기 (REQ-J06)
```mermaid
flowchart TD
  A["업체: 일정 취소"] --> B["영향 지원자(APPLIED/SELECTED/CONFIRMED) 일괄 알림, CANCELED_BY_SYSTEM"]
  C["업체: 일정 연기 (새 시작/종료)"] --> D["새 일정+역할 복제, 원 일정 POSTPONED"]
  D --> E["원 지원 SELECTED/CONFIRMED → 새 일정에 SELECTED 새 지원 행(moved_from) 생성"]
```

## 11. 정산 (REQ-PC10) — P2
촬영 종료 → 출퇴근 기록으로 근무분 확정 → 기본급(규칙: 9시간 이내 시급×8, 초과 시 시급×시간) + 식대·교통·연장·공제를 `settlement_items` 로 입력 → 세금 유형 선택·세액 기록 → **은행 대량이체 엑셀** / **원천징수 자료 엑셀(암호화, 주민번호 포함)** 생성 → 업체가 계좌로 직접 이체 후 `PAID` 표시. **플랫폼은 송금하지 않는다.** 은행별 양식은 실제 양식을 받은 뒤 `export_templates` 에 추가한다.

## 13. 증빙 보관 · 파기 (REQ-PC15, A06)
지원서(스냅샷·서명·현재 사진·해시)·출결·정산·메시지·주민번호(버전)·상태 이력을 **분쟁 대비 증빙으로 보관**한다. 보존기간은 `evidence_retention_years`(기본 5년, 법정 보존기간 확인 후 확정), 분쟁/조사 중이면 법적 보류. 경과분은 `EvidenceRetentionPurger` 가 파기(주민번호·계좌 먼저, 지원서·사진은 비식별화 후 통계만). 탈퇴한 출연자의 데이터도 같은 기준으로 보관·파기한다.

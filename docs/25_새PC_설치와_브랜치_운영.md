# 25. 새 PC 설치 · 브랜치 운영 · 확정 사항 요약 (v1.3, 2026-10-28 사용자 환경에서 검증)

> 이 문서만 따라 하면 **새 PC(또는 새 WSL)에서 저장소를 받아 그대로 돌아간다.** 실제로 사용자 WSL2(Ubuntu 24.04)에서 겪은 문제와 해결을 포함했다.

## 1. 브랜치 운영 (확정)
| 브랜치 | 용도 | 누가 |
|---|---|---|
| `dev/mk` | **받아서 쓰는 기준 브랜치.** Claude 가 슬라이스를 끝낼 때마다 최신으로 갱신 | Claude(사용자는 `pull` 만) |
| `claude/sharp-gates-23o2zd` | Claude 작업 브랜치(슬라이스마다 푸시, `dev/mk` 와 같은 커밋) | Claude |
| (선택) `main` | 첫 폐쇄 베타 때 만들 안정 브랜치 | 추후 |

**사용자가 하는 일은 이것뿐이다 (브랜치 관리는 Claude 가 한다):**
```bash
git checkout dev/mk && git pull
```
`dev/mk` 에 직접 커밋하지 않는다(코드는 Claude, 실행·확인은 사용자). 직접 고치고 싶은 것이 있으면 Claude 에게 요청한다.

## 2. 처음부터 설치 (Windows 11 + WSL2 Ubuntu 24.04)
### 2-1. WSL 만들기 (PowerShell)
```powershell
wsl --install -d Ubuntu-24.04
```
`C:\Users\<이름>\.wslconfig` 에(권장):
```
[wsl2]
memory=8GB
processors=4
swap=4GB
vmIdleTimeout=-1
```
저장 후 `wsl --shutdown`.

### 2-2. 필수 도구 (WSL 안, 한 번만)
```bash
sudo apt update && sudo apt install -y git curl zip unzip
```
**Docker Engine** (Docker Desktop 아님):
```bash
curl -fsSL https://get.docker.com | sudo sh
```
```bash
sudo usermod -aG docker $USER
```
WSL 창을 닫았다 다시 연다. Docker Desktop 을 한 번 설치했던 PC 에서 `docker-credential-desktop.exe not found` 가 나오면:
```bash
echo '{}' > ~/.docker/config.json
```
**JDK 25 (Temurin, GPL+Classpath Exception → 상업 이용 가능):**
```bash
curl -s "https://get.sdkman.io" | bash
```
```bash
source ~/.sdkman/bin/sdkman-init.sh && sdk install java 25-tem
```
**Node 24 LTS** (웹 작업 때): `nvm` 설치 후 `nvm install 24`.

### 2-3. 저장소 받기
```bash
mkdir -p ~/work && cd ~/work
```
```bash
git clone -b dev/mk https://github.com/7fsikMinQ/O.git bojohelp
```
```bash
cd bojohelp
```
프로젝트는 반드시 WSL 홈(`~/`) 아래에 둔다(`/mnt/c/...` 는 매우 느림).

### 2-4. 한 번에 점검·기동·시험
```bash
tools/dev/bootstrap.sh --check
```
✘ 가 없으면:
```bash
tools/dev/bootstrap.sh
```
(DB 기동 → 백엔드 시험까지. 시험 119건 전부 통과해야 한다.)

## 3. 매일 쓰는 명령
| 하고 싶은 것 | 명령 |
|---|---|
| WSL 열기 | Windows Terminal/PowerShell 에서 `wsl` — **이 창을 닫지 말 것**(SSH 로만 접속하면 WSL 이 유휴 종료되어 시험·서버가 끊김) |
| DB 기동 | `tools/dev/up.sh` |
| 서버 실행 | `cd backend && ./gradlew bootRun` (창 A 에 계속 둠) |
| 명령 입력 | 새 `wsl` 창(창 B) |
| 시험 | `cd backend && ./gradlew test --no-daemon` |
| 최신 코드 반영 | 서버 `Ctrl+C` → `git pull`(또는 위 merge) → `./gradlew bootRun` |
| DB 초기화 | `tools/dev/reset-db.sh` (개발 DB 전용) |
| 웹 | `cd web && npm install && npm run dev` |
| 앱 | Flutter 3.47.8 설치 후 `cd app && flutter pub get && flutter analyze && flutter test` |
| 관리자 계정으로 서버 켜기 | `export ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='Admin12345678'` 후 `./gradlew bootRun` (첫 기동 때 1명 생성, 이메일·비밀번호는 로그에 안 남음) |
| 전체 설계 검증 | `tools/verify_all.sh` (PostgreSQL 클라이언트 필요) |

## 4. 겪었던 문제와 해결
| 증상 | 원인 | 해결 |
|---|---|---|
| SSH 접속이 `connection refused`, 도중에 끊김, 컨테이너가 사라짐 | SSH 만 접속하면 WSL 이 "미사용"으로 유휴 종료 | `wsl` 창을 연 채로 작업, `.wslconfig` 의 `vmIdleTimeout=-1` |
| `sdkman` 설치 중 zip 없음 | 패키지 누락 | `sudo apt install -y zip unzip` |
| `java -version` 이 1.8 | 기존 Java 8 | `sdk install java 25-tem` 후 기본으로 설정 |
| `docker-credential-desktop.exe` 없음 | Docker Desktop 흔적 | `echo '{}' > ~/.docker/config.json` |
| `bootRun` 에서 `Migration checksum mismatch for migration version 1` | 첫 배포 전 V1 재생성 정책 | `tools/dev/reset-db.sh` |
| 5432 포트 충돌 | 다른 PostgreSQL | `.env` 에서 `DB_PORT=5433` 과 `DB_URL` 의 포트를 같이 변경 |
| `wsl` 로 들어가면 `/mnt/c/...` | PowerShell 위치를 따라감 | `cd ~/work/bojohelp` 또는 `wsl ~` |

## 5. 지금까지 확정된 것 (요약, 원문은 CLAUDE.md)
- **제품**: 보조출연 헬프. 업체 공고 → 출연자 지원(현재 사진+전자서명) → 합격 통보 → 참여 확정. 수수료 0원, 현재 전 기능 무료, 추후 업체 구독.
- **시간**: 공고·합격서의 시간은 예상(집합 ±2h, 종료 ±4h), 합격서에 금액 없음, 근로계약서는 현장 실물.
- **돈**: 플랫폼은 송금하지 않음(정산·이체·원천징수는 기능 플래그 기본 OFF).
- **로그인**: 출연자 = 휴대폰 + 문자 숫자 6자리(비밀번호 없음, 90일 유지), 업체·관리자 = 이메일 + 비밀번호.
- **⭐ 출연자**: 업체가 ⭐ 로 표시한 출연자에게 새 공고 알림을 1분 먼저(시간 직접 지정은 추후 구독).
- **UI**: 주 사용층 20~40대, 쉬운 말, 본문 16px·버튼 52px, 파스텔·라이트/다크.
- **스택**: Spring Boot 4.1.2 + JDK 25 + PostgreSQL 18, React 19 + Vite 8, Flutter 3.47.8, 서버 Lightsail 서울 + Cloudflare.

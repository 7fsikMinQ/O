## 3. Apple App Store (iOS 앱은 추후, 지금은 iPhone 웹)
- 계정 삭제를 **앱 안에서 시작**할 수 있어야 함(⭐ 공식). 본인 확인 단계 허용, 지나치게 어렵게 만들면 반려.
- 카카오 등 **제3자 로그인만 제공하면 동등한 대안 로그인(Sign in with Apple 등) 요구** 가능(가이드라인 4.8 — 이번 검색에서 원문 미확인 ❓, 제출 시 확인). 휴대폰 번호 로그인을 기본으로 두면 영향이 줄 수 있으나 심사 판단.
- 사용자 생성 콘텐츠: 신고·차단·연락처 제공(1.2 ❓ 원문 확인) — 메시지 차단·신고로 대응.
- Apple Developer 연 US$99, 개인정보 영양 성분(Privacy Nutrition Label) 작성.
- 웹앱(PWA)은 심사 없음 — 이미 Flutter 웹으로 iPhone 지원(W2 게이트).

## 5. 내 회사(업체)에서 쓰는 경우
- 운영자=업체 겸업은 허용으로 확정(13번 §6). 자사 직원은 OWNER/MANAGER/SCHEDULER/STAFF 역할로 같은 기능 사용 — 별도 코드 불필요.
- **타 업체 지원자 정보로 자사 영업 금지**를 약관·내부 원칙으로 명시(감사 로그로 사후 확인 가능).
- 자사 현장 데이터와 시험 데이터는 분리(운영 DB 에 시험 계정 금지, 개발 DB 에 실데이터 금지).

## 8. 추가하면 좋은 기능 제안 (우선순위순, 모두 무료·소규모) — **1·3·4번은 확정·반영됨(REQ-PC18~20)**, 로그인 문자 방식도 확정
1. **길찾기/전화 버튼**: 집합 장소 "지도 열기"(네이버·카카오 지도 링크, SDK 불필요), 반장·업체 "전화하기"(tel:). 현장 도착 실패 감소.
2. **한 번에 다시 지원**: 이전 지원서의 사진·정보 재사용("지난번 그대로 지원"). 입력 부담 감소.
3. **현장 공지 읽음 확인**: 단체 메시지 읽음/미읽음 목록(업체), 미읽음에게 문자 재안내(옵트인).
4. **자주 쓰는 출연자 명단(내 팀)**: 업체가 이전 합격자를 "⭐"로 저장해 다음 공고 때 먼저 알림(구독 후보).
5. **출연 이력 증명 PDF**: 출연자가 본인 출연 횟수·업체 확인서 다운로드(이력서용, 업체 확인 필요).
6. **간편 문의**: 앱 안 "전화/카톡 문의" 버튼, 자주 묻는 질문(쉬운 말).
7. **일정 변경 알림 묶음**: 집합 시간·장소 변경 시 합격자 전체에 한 번에(이미 단체 메시지로 가능, 템플릿 추가).
8. 이후: 공고 알림 키워드, 업체 평가는 P3 유지.

## 2. 접근 통제 원칙
- 최소 권한·기본 거부. 플랫폼 RBAC + 업체 직책 + 담당 일자 + 상태(합격 여부) 4중 검사(03 부록 A·B).
- 민감 열람·다운로드(`ROSTER_VIEW`, `ROSTER_EXPORT`, 동의서 열람, 관리자 조회)는 **감사로그 필수**.
- 응답 마스킹 단일 정책 클래스(`F-OP13`) — 컨트롤러/쿼리마다 개별 구현 금지.
- 인원정보표 뷰는 **백엔드 전용**(BI·직접 SQL 노출 금지).

## 4. 약관·동의 설계
- 필수: 서비스 이용약관, 개인정보 수집·이용. 분리 동의: **제3자 제공**(합격 후 업체에 연락처·계좌 제공, 이력 공개), 마케팅 수신(선택), 위치정보(GPS 출석 사용 시), 청소년/법정대리인.
- 약관은 `terms` 버전으로 관리, 동의는 `user_consents` 에 시각과 함께 기록. 개정 시 재동의 흐름.
- 개인정보 처리방침에 **수탁·국외 이전**(FCM=Google, R2=Cloudflare, 메일/Sentry 등) 명시.
- 광고성 정보 수신 동의와 야간(21~08시) 발송 제한 준수(`REQ-N05`).

## 6. 이해충돌 방지 (운영자 = 보출 업체)
1. 운영자(ADMIN/OPERATOR) 계정과 자사 업체 계정(COMPANY)은 **별개 사용자**로 운영한다.
2. 자사 업체도 승인 절차·공개 규칙·마스킹·감사로그가 동일하게 적용된다. 관리자 권한으로 자사에 유리하게 노출(상단 고정 등)을 하지 않는다.
3. 타 업체의 지원 데이터·출연자 이력을 **자사 영업 목적으로 활용하지 않는다**(약관·내부 규정에 명시, 접근은 감사로그 대상).
4. 향후 유료 노출 상품은 모든 업체에 동일 조건으로 판매한다.

## 7. 사고 대응
1. 탐지(알림/신고) → 2. 격리(키 회전, 토큰 폐기, 해당 계정 차단) → 3. 범위 파악(감사로그·접근 로그) → 4. 법정 통지·신고 의무 확인(개인정보 유출 시) → 5. 이용자 안내 → 6. 재발 방지·사후 보고서.

# 13. 보안 · 개인정보 · 법무 체크리스트 (v1.1)

> 2026-10-28 · ⚠️ **법률·세무 자문이 아니다.** 법령은 개정되므로 오픈 전 노무사·세무사·개인정보 전문가 확인이 필요하다. 아래 조항 언급은 확인 대상 지목이다.
> v1.1 은 사용자 요구로 **주민등록번호 수집(필수)·지원서 전자서명·증빙 전부 보관**이 추가되어 위험이 커졌다. 이 문서는 요구를 구현하되 노출면을 최소화하는 방법과 반드시 확인할 법적 쟁점을 정리한다.

## 2. 접근 통제 원칙
- 최소 권한·기본 거부. 플랫폼 RBAC + 업체 직책 + 담당 일정 + 상태(지원/합격) 4중 검사(03 부록 A·B).
- **휴대폰은 지원 단계부터 업체 공개**(사용자 정책) — 동의 문구와 처리방침에 명시하고, 업체의 목적 외 이용 금지를 약관에 둔다.
- 주민번호·계좌 열람/내보내기, 인원 정보표 열람, 동의서 열람은 `audit_logs` 필수.
- 마스킹 단일 정책 클래스(`F-OP15`). 뷰는 백엔드 전용.

## 4. 약관·동의 설계
- 필수: 서비스 이용약관, 개인정보 수집·이용, **제3자 제공**(휴대폰·합격 후 정보를 지원한 업체에 제공), **고유식별정보(주민번호) 처리 동의**(별도 분리), **전자서명·증빙 보관 동의**.
- 선택: 마케팅 수신, 이력 공개(역대 합격 이력의 업체 열람) 동의 — 철회 가능.
- 약관은 `terms` 버전, 동의는 `user_consents` 시각 기록. 개정 시 재동의.
- 처리방침에 **수탁·국외 이전**(FCM=Google, R2=Cloudflare, 메일, Sentry 등)과 보존기간을 명시.
- 광고성 정보 야간(21~08시) 제한 준수.

## 6. 운영자=업체 겸업
사용자는 "상관없다"고 했으므로 별도 통제를 의무로 두지 않는다. 다만 **타 업체의 지원자 정보·이력을 자사 영업에 활용하지 않는다**는 내부 원칙과 관리자 열람의 감사로그는 분쟁 방지를 위해 유지하길 권장한다.
